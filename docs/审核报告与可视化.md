# 审核报告与可视化

> 本文描述**当前实现的两个审核报告页面**、13 类风险规则扫描、条款完整性展示、风险原文定位与导航交互。
> 涉及代码：`frontend/src/views/contract-detail/ReportPanel.vue`（审核报告 Tab）、`frontend/src/views/AuditReportDetail.vue`（独立完整审核报告）、`frontend/src/views/AuditReport.vue`（报告列表）、`frontend/src/constants/reportTokens.js`、`frontend/src/constants/riskTypes.js`、`frontend/src/constants/navigation.js`；后端 `GET /contracts/{id}/audit-report`、`GET /contracts/{id}/audit-result`、`GET /contracts/{id}/clause-comparison`。

---

## 一、两个页面，两个职责

系统有**两个实际页面**在用审核报告，定位严格区分：

| 页面 | 路径 | 定位 |
|---|---|---|
| **审核报告 Tab**（`ReportPanel.vue`，在合同详情内） | `/contracts/:id?tab=audit` | **审核结果驾驶舱**：结论 + 结构化画像 + 规则扫描 + 条款完整性 + 重点风险摘要 + 操作入口。**不做正式报告排版，不展开每条风险的完整证据与建议。** |
| **独立完整审核报告**（`AuditReportDetail.vue`） | `/audit/report/:contractId` | **正式《合同智能审核报告》**：合同基本信息 + 审核结论 + 风险概览 + 完整风险详情 + 条款完整性 + 关联风险 + 合同原文 + 打印。 |

另有一个**报告列表页** `AuditReport.vue`（`/audit/report`）：列表 + 右侧内联预览（评分环、高/中/低统计卡、ECharts 饼图与柱图、风险明细表），提供「全屏查看」跳转到完整报告。它不是完整报告的重复实现。

> **命名陷阱**：query 取值 `?tab=audit` 指向的是**「审核报告」Tab**（内部 pane 名为 `report`），而内部 pane 名 `audit` 指向的是**「风险详情」Tab**。翻译只能通过 `navigation.js::paneFromQueryTab()`。

### 数据来源（不新增任何接口）

| 数据 | 接口 |
|---|---|
| 报告统计（`risk_score` / 高·中·低计数 / `missing_clauses`） | `GET /api/contracts/{id}/audit-report` |
| 当前批次风险记录（含 `evidence` / `recommendation`） | `GET /api/contracts/{id}/audit-result` |
| 条款比对结果 | `GET /api/contracts/{id}/clause-comparison` |
| 合同类型 / `extracted_elements` / `audit_mode` | `GET /api/contracts/{id}` |
| 合同原文（PDF 渲染） | `GET /api/contracts/{id}/file` |

完整审核报告用 `Promise.allSettled` 并行加载，**单个接口失败只影响它自己的区块**。它**刻意不调用** `/clause-comparison`（避免触发后端 LLM 重算），条款数据直接取 `audit-report` 里的 `missing_clauses`。

## 二、审核报告 Tab（`ReportPanel.vue`）的结构

内容按以下顺序渲染（有报告或风险数据时才进入正常态；否则显示加载骨架 / 错误 + 重试 / `审核尚未完成，暂无审核报告` + 「开始审核」）。

### A. 审核结论（顶部通栏）

只做**事实陈述**，数字全部来自后端真实字段，不写「建议不要签署 / 不合格 / 存在重大法律问题」这类评价性结论：

- 有风险：`本次审核发现 N 项风险（高 X / 中 Y / 低 Z）`（只列非零等级）；
- 无风险：`本次审核未发现 R01–R13 风险项`；
- 追加项：`,条款覆盖率 P%`、`,缺失关键条款 M 项`。

### B. 双列区（≥1200px 双列，<1200px 单列堆叠）

#### B1 合同结构化画像（标注「来自合同解析结果」）

字段全部来自 `contract.extracted_elements`，**缺失即整项不渲染**：合同类型、`parties` 的各键（现场真实数据是「甲方 / 乙方」）、合同金额（`amountParts`：币种符号 + 千分位 + 大写原文）、签订日期、履行期限、争议解决、适用法律。全部缺失时显示「本次解析未提取到结构化要素。」

随后是**风险评分**：数值 + 轻量位置条 + 说明 `满分 100 · 分数越高风险越高`。颜色沿用项目既有阈值（`scoreColor`：≥60 红 / ≥30 橙 / 其余蓝），**没有新增评分阈值**，后端 `risk_score` 的计算方式也未改动。

> `risk_score = min(100, 高风险×30 + 中风险×15 + 低风险×5)`，在后端审核时一次性算好并存入 `audit_reports.risk_score`。

#### B2 风险规则扫描（13 类规则的扫描矩阵）

这是任务清单中「13 类风险规则扫描」的落地实现：

- 矩阵**恒为 13 个格子**，编号与名称来自 `constants/riskTypes.js` 的 `RISK_NAMES`（**R01…R13**，与后端 `recommendation_engine.RISK_NAMES` 逐条对齐）；
- 每格两行、居中：第一行 **R 编号**（等宽体），第二行 **中文风险名称**（逐字取表，不缩写、不截断）；
- **命中格**：`button`，背景色 = 该规则命中记录中**最高风险等级**对应的颜色，可点击 → 复用既有风险详情深链跳转到完整报告对应风险卡（`/audit/report/:id#risk-<记录id>`）；同一规则命中多条时取**判断把握度最高**的一条（与「重点风险」同序）；tooltip 显示 `Rxx · 名称` / 等级 / `本次命中 N 条记录`（N>1 时）/ `点击查看风险详情`；
- **未命中格**：浅灰底 `div`，文字结构与命中格**完全一致**，但**无 `@click`、无 `role=button`、无 `tabindex`、无 hover 效果**，不跳转、不弹窗、不改 URL、不伪造记录；tooltip 文案为 `本次审核已扫描该规则，未发现风险。`；
- 说明行：`共扫描 13 类风险规则 · 命中 M 类` + `彩色＝发现问题，可点击查看详情；灰底＝已扫描、未命中`。

> **口径本身很重要**：**13 类规则均执行，不代表 13 类都存在风险。** 命中状态只来自**本次审核**结果（`riskItems` 的 `risk_type`），**不查历史批次、不跨批次去重、不从页面文本推测**。
>
> 另需注意：代码中**没有**「本次发现风险 / 本次未发现风险」这两个字面标签，区分方式是**命中 / 未命中**（彩色可点 / 灰底不可点）。

矩阵下方是**风险等级分布**：横向堆叠条 + 图例（高风险 / 中风险 / 低风险 + 计数），计数为 0 的等级不产出图例段；全部为 0 时显示「本次审核未检出风险项。」

### C. 条款完整性

**仅在存在可用的逐条比对数据时渲染**（`clauseComparison` 有 `summary`，或报告的 `missing_clauses` 是带 `summary` 的字典；数组 / null 视为「无逐条比对结果」）。

展示内容（数字与条款名逐字来自当前比对结果，**不硬编码任何条款名或数字**）：

| 内容 | 来源 |
|---|---|
| `共 N 项标准条款` | `cmpSummary.total` |
| **覆盖率** | `Math.round(cmpSummary.coverage_rate × 100)%`（非数值时显示 `—`） |
| 分布条 | 已覆盖绿 / 部分偏离橙 / 缺失红 |
| **已覆盖 / 部分偏离 / 缺失** 三个计数 | `summary.covered` / `summary.partial` / `summary.missing` |
| `存在问题 P 项 · 其中 M 项为关键条款` | `P = 缺失数 + 部分偏离数`；`M` = 关键缺失数 |
| **缺失（N 项）** 标签组 | 每条可点击；**关键缺失**判定完全来自后端 `missing_critical`（红色 `is-critical` 且排在前），普通缺失为灰色 `is-plain` |
| **部分偏离（N 项）** 标签组 | 全部可点击（橙色） |
| **已覆盖 N 项标准条款** | **默认收起**，可「展开 ▾ / 收起 ▴」，展开为 3 列自适应网格 |

**缺失与部分偏离条款可点击**：点击后统一跳转到完整审核报告的**「条款完整性检查」章节**（锚点 `#clauses`）。完整报告目前**没有条款卡片级 anchor**，因此这里**不做下标猜测、不新建第二套定位机制**，只做章节级降级定位。

刻意**不展示**：`similarity` / `deviation` / `matched_text` / `confidence` / 风险等级。理由（代码注释）：**条款缺失 ≠ 风险命中**，把两者混在一起会误导用户。

卡片标题栏右上角有「完整报告 ↗」按钮；卡片说明为「按标准条款清单逐项比对」。

### D. 关联风险（跨条款）

**仅在后端真的返回了 `cross_clause_risks` 时渲染**；为空时**整个区块不产出**（不显示「暂无关联风险」制造空白模块）。

内容：`前置依赖缺失`（danger 标签）/ `条款互斥冲突`（warning 标签）+ 风险说明 + `条款 → 依赖：X` 或 `条款 → 与「Y」互斥`。数据来自 `matcher._cross_clause_risks()` 的图分析（利用标准条款库的 `depends_on` / `conflict_with` 字段）。

### E. 重点风险（摘要）

- 按 **高 → 中 → 低** 分组（空分组不产出），组内按**判断把握度降序**；
- 每条给：等级标签、**中文风险名**（业务名优先，R 编号弱化显示）、判定理由（缺失时显示「后端未给出判定理由」）、**判断把握度百分比**（中性灰圆点 + 百分比，**不复用风险等级色**，tooltip 明确「表示模型对该风险识别的确定程度，与风险严重程度无关」）、检测方式标签（规则引擎 / 检索引用 / 多智能体验证 / 证据裁决）、「详情 →」按钮；
- 「详情 →」→ 跳完整报告 `#risk-<id>`；
- 本 Tab **不展开**每条风险的完整证据与建议，完整内容在完整报告里。

### F. 操作区

**只有两个真实入口**：

- **「查看完整审核报告」** → `/audit/report/{contractId}`；
- **「去修改合同」** → 切到「修改合同」Tab。

右侧显示 `审核时间 <时间>` 与 `审核方式 精细审核 | 快速初筛`。

> 代码注释明确：后端没有报告导出 / 模板配置能力，因此这里**不放任何占位按钮**。

### 页脚口径说明

页面底部如实说明快照语义：**本区数字为「审核时」的快照** —— 风险评分与高/中/低计数**不随之后的条款比对刷新而变化**；条款覆盖率取自**最近一次**比对结果；「风险规则扫描」的命中状态与「重点风险」均取**本次审核**结果。

## 三、独立完整审核报告（`AuditReportDetail.vue`）

### 3.1 工具条（打印时整体隐藏）

面包屑 `审核中心 / 审核报告 / 报告详情`、「返回报告列表」、`查看审核历史`（→ `/audit/result/{id}`）、**「打印报告」**（`window.print()`）。

右下角固定悬浮按钮 **「← 返回审核报告」**（`z-index: 1000`，任意滚动位置可见，打印时隐藏）→ 跳 `/contracts/{id}?tab=audit`，由合同详情读取 query 落位并恢复滚动位置。

### 3.2 报告主体章节

| 章节 | 内容 |
|---|---|
| **报告头部** | 标题固定为 **《合同智能审核报告》**；副标题 `合同类型 · 文件名`；meta 信息为 `审核时间` / `审核方式` / `审核状态 <合同状态>`；信息网格：当事人（按 `parties` 各键）、合同类型、合同金额、签订日期、履行期限、争议解决、风险评分、`风险项 N 项`（子说明为高风险 x 项、中风险 y 项…）；另有通栏「适用法律」格 |
| **失效提示**（条件渲染） | 当后端 `has_current_result` 为 false 且仍有风险记录时显示 `该合同的当前审核结果已被驳回，以下内容为已失效的历史审核结果` |
| **01 审核结论** | 一段话结论（风险项数 + 各等级 + 条款完整性覆盖率及 标准条款/已覆盖/部分偏离/缺失 明细 + 关键条款缺失数）+ 复核建议 + 固定免责声明 `本报告由 AI 合同审核系统自动生成，仅供法务与业务参考，不构成法律意见。` |
| **02 风险概览** | 风险评分**圆环**（`el-progress type="circle"`，颜色沿用 ≥60/≥30 阈值）+ 高/中/低三行计数与比例条 |
| **03 风险问题明细** | 按等级分组（高→中→低，组内按把握度）的**完整风险卡**，见 3.3 |
| **04 条款完整性检查** | `<section id="clauses">`；5 个指标块（覆盖率 / 标准条款 / 已覆盖 / 部分偏离 / 缺失）+ 堆叠分布条与图例 + **缺失关键条款**红色标签 + `标准条款逐项比对 共 N 条`（每条：状态徽章、条款名、优先级「必需条款 / 建议条款」、`相似度 NN%`，以及 合同中匹配条款 / 偏离说明 / 补全建议 / 风险说明 / 相关法条）；无数据时显示 `本次审核报告中未包含条款比对结果（审核时比对未完成或该次比对未产出逐条结果）。` |
| **05 关联风险** | 仅当跨条款风险非空时渲染（章节编号动态生成，因此缺席时不会出现编号断档） |
| **06 合同原文** | pdf.js 阅读器：加载态提示 `Word 文档由后端实时转换为 PDF，首次加载可能需要数秒。`；页码导航（上一页 / `第 X - Y / Z 页` / 下一页 / 跳至指定页）；≥900px 双页并排、以下单页；失败文案区分 404、其它错误、以及「后端回退返回了原始 Word 文件」 |
| **原文定位对话框** | `el-dialog`（880px）：**只做逐字匹配**，不推算页码/坐标；`上一处 / n / N / 下一处` 逐处跳转并高亮 |

**打印**：全局 `@media print` 隐藏工具条、导航、返回按钮、风险导航与 PDF 工具条，并 `print-color-adjust: exact` 保留颜色。

### 3.3 单张风险卡的字段

| 字段 | 来源 |
|---|---|
| 等级徽章 + 中文风险名 + R 编号 | `risk_level` + 前端风险名映射 |
| **涉及条款**（+ `第X条 · 标题`） | `clause_text` + `clause_position` |
| **原文证据**（+ `字符区间 a–b`） | `clause_position.original_text` / `start` / `end` |
| **风险分析** | `reason` |
| **修改建议**（+ 修改示例） | `suggestion` / `recommendation.example` |
| **风险说明** | `recommendation.risk_description` |
| **法律依据**（+ 命中法条 / 依据） | `recommendation.legal_basis` / `evidence.law` |
| **接地检查警告** | `recommendation.grounding` 未通过时显示 `该建议含未经证据核实的数值，请结合合同原文确认。（问题列表）` |
| 元信息 | `检测方式 · 判断把握度 NN%` + 定位状态标签（`已定位原文` / `可定位（原文逐字匹配 N 处）` / `未在原文中定位到该条款` / `合同正文不可用`） |
| 操作 | **「查看原文」**（打开逐字定位对话框）与 **「去修改此条款」**（写 `sessionStorage['a24_revise_source']` 后跳合同详情的「修改合同」Tab） |
| **风险卡间导航** | `← 上一项风险 / n / N / 下一项风险 →`，只在**风险卡之间**移动（不进入条款完整性 / 合同原文等章节），**不改变 URL** |

锚点：每张风险卡渲染 `id="risk-<风险记录id>"`（由 `navigation.js::riskAnchorId` 统一生成，与深链解析同源），并设 `scroll-margin-top: 80px`。

> **建议层文本清理**：建议层文本会经 `cleanAdviceText()` 做**显示层**替换——把后端 LLM 留在括号里的内部字段名标记（如 `has_consideration为false`、`basis_evidence为空`）改写为业务措辞（「未约定对价」「合同中未载明验收依据」）。该函数**绝不用在合同正文类字段**（`clause_text` / `matched_text` / 锚点原文），那些必须逐字保持原样。

### 3.4 明确**不存在**的能力

以下项目在报告中**没有实现**，文档不得写成存在：

| 项目 | 结论 |
|---|---|
| PDF 正式导出接口 | **没有**。唯一“导出”动作是浏览器打印对话框。 |
| Word / DOCX 报告导出接口 | **没有**。（`GET /contracts/{id}/revised-docx` 导出的是**修订版合同**，从「修改合同」工作台下载，不是报告。） |
| 审核人 | **不显示**（后端无此字段）。 |
| 报告编号 | **不显示**（后端无此字段）。 |
| 报告版本号 | **不显示**（后端无此字段）。 |
| 审批状态 | **不显示**。头部出现的「审核状态」是**合同状态**（已上传 / 已解析 / 审核中 / 审核完成 / 待验收 / 已验收），不是审批状态。 |
| 审核时间 / 审核方式 | **显示**。 |
| 合同基本信息 | **显示**（由 `extracted_elements` + 合同字段构成，缺字段即隐藏）。 |

## 四、风险原文定位

系统在三处提供「风险 / 条款定位到合同原文」的能力，层次不同：

| 场景 | 实现 | 是否调 LLM | 是否写库 |
|---|---|---|---|
| 审核阶段自动定位（产生锚点） | `_locate_clause` / `_locate_at` → 写入 `audit_records.clause_position` | 否 | 是（审核事务内） |
| 用户主动定位（只读工具） | `POST /contracts/{id}/locate-clause` | **否** | **否** |
| 报告页逐字查看（前端定位） | 在完整报告「合同原文」对话框里做**逐字匹配**并高亮 | 否 | 否 |

### 4.1 审核阶段的定位口径

用 LLM 证据文本的**前缀**在 `parsed_text` 中逐级缩短查找（30→20→10→6→4 字），容忍证据对原文的改写；多命中时用「（N）子项」消歧，**无法唯一消歧则显式失败**（不随便取第一个）；命中处截取子条款窗口（边界为（N）子项 / 句号 / 分号 / 换行，上限 150 字），并从最后一个「第X条」标题解析真实条号。

结果包含 `{clause_no, clause_title, original_text, start, end}`，其中 **`original_text` 就是 DOCX 导出使用的逐字原文锚点**。

原文文本 Tab 里对**未建立锚点的风险**不标位置，并在提示条中如实告知数量（「不伪造位置」）。

### 4.2 只读定位工具（`locate-clause`）

定位优先级：① 条款编号锚点（`clause_anchor`，支持中文/阿拉伯数字，窗口为整条、上限 1200 字）→ ② 原文精确匹配（唯一命中直接返回，多处命中复用同一消歧逻辑，仍无法唯一则返回候选列表）→ ③ 前缀匹配 → ④ 关键词匹配（自然语言描述的纯确定性处理：切词、去停用词、回溯最长可命中子串、按「是否唯一 / 长度 / 字典序」确定性排序）。

返回 `{found, clause_no, clause_title, original_text, start, end, match_mode, candidates, reason}`。

**语义要点**：只有 `original_text` 是可提交给 `/revise` 的逐字原文；`found=true` 只表示「在正文中定位到候选」，**不代表后端已建立 revision 锚点**（锚点只在 revise 写库时建立）。

## 五、导航与返回位置记忆

完整链路：

```
合同详情 → 审核报告 Tab → 风险详情（#risk-<id>）→ 完整审核报告
   → 「返回审核报告」 → /contracts/:id?tab=audit → 恢复审核报告 Tab 的滚动位置
```

| 机制 | 实现 |
|---|---|
| Tab 深链 | `/contracts/:id?tab=audit\|report\|text\|compare\|revise`；未知/空/数组 → 返回空串，**保持默认行为**（停在「原始文本」） |
| 风险深链 | `#risk-<纯数字记录id>`；由完整报告 `scrollToHash()` 消费；同页 hash 变化会重新滚动 |
| 章节锚点 | `#clauses` → 完整报告「条款完整性检查」章节；条款缺失/偏离 Tag 统一降级到该锚点 |
| 风险上一项 / 下一项 | **仅在完整审核报告页**；按显示顺序滚动；不改 URL |
| 位置采集 | `onBeforeRouteLeave`：仅当仍停在审核报告 Tab 时写 `sessionStorage['contract_<id>_report_return'] = {tab:'audit', scrollY}` |
| 位置恢复 | 进入 `?tab=audit` 时**一次性消费**（读取即删除），`nextTick` + `requestAnimationFrame` 轮询直到可滚到目标（上限 1500ms），再以 `behavior:'auto'` 滚动 |
| 为什么采集点在离开合同详情 | 两页滚动坐标不可比（完整报告可达数千像素，审核报告 Tab 只有几百像素），用前者的 Y 恢复会被截断成「贴底」 |
| 明确不做 | 不写数据库、不新增接口、不跨会话保存；普通进入或刷新不会跳回旧位置 |

另一条独立的跨页传递：风险明细 / 完整报告点「去修改此条款」会写 `sessionStorage['a24_revise_source'] = {source:'risk', risk_id}`，由合同详情读取后**立即删除**并切到「修改合同」Tab、选中对应会话；若该风险没有会话，则给出提示而不是静默失败。

## 七、可视化设计上的克制之处（可作为评审要点）

1. **只画真实字段**：所有数字来自后端；缺字段就隐藏该项，不做推导、不显示占位 0。
2. **不混淆概念**：规则扫描矩阵的「命中/未命中」表述的是**规则扫描覆盖面 + 命中情况**，不是「合同好坏」；条款「缺失」明确不等于 R01–R13 风险命中，因此完整性区块不展示风险等级。
3. **不伪造交互**：未命中的规则格不可点、无 hover；未建立锚点的风险不在正文标位置。
4. **快照语义写在页面上**：风险评分与等级计数是审核时快照，条款覆盖率取最近一次比对，矩阵与重点风险取本次审核结果——这三点在页脚明确说明，避免用户误读为同一时点数据。
5. **深色/彩色只用于表达真实状态**：命中格颜色取实际命中的最高风险等级色；「判断把握度」刻意用中性灰，避免被误读为严重程度。
