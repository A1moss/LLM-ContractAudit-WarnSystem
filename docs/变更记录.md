## 二、变更条目

### C-008 · 用户个人 DeepSeek Key 真正生效（个人 Key > .env 默认 Key） 【未提交】

- **日期**：2026-09-15
- **范围**：LLM Key 解析链路 + 个人信息页（**业务判定逻辑零改动**）
- **背景**：此前「个人信息」页的 Key 只写浏览器 localStorage、后端完全不读，用户以为配好了但实际仍用 `.env` 的全局 Key（C-005 只读审查发现的功能缺口）
- **最终规则**：**个人 Key > .env 系统默认 Key**；无个人 Key 回退默认；两者都无 → 明确配置错误

**改动内容**

| 文件 | 改动 |
|---|---|
| `backend/ai/llm_context.py`（新增） | 用 `ContextVar` 绑定"本次请求用哪个 Key"；`submit_with_context()` 把上下文复制进线程池工作线程 |
| `backend/services/user_secret.py`（新增） | 个人 Key 的 **Fernet 加密**存取（密钥由 `SECRET_KEY` 派生）；仅内部返回明文，接口永不回显 |
| `backend/ai/llm_client.py` | `DeepSeekClient` **不再保存 api_key**；每次 `chat()` 按上下文解析 Key，按 Key 哈希缓存 OpenAI client；缺 Key 抛 `LLMConfigError`；**取消 import 期硬校验**（改为调用期，否则"用户自配 Key"的部署起不来） |
| `backend/main.py` | 新增 `users.deepseek_api_key_enc` 列迁移；新增**请求级 Key 绑定中间件** |
| `backend/models/user.py` | 新增 `deepseek_api_key_enc` 列（密文） |
| `backend/api/auth.py` | 新增 `GET /auth/profile`、`PUT/DELETE /auth/profile/deepseek-key`；`GET /auth/users` 增加 `deepseek_key_configured`（**只回布尔**） |
| `backend/api/deps.py` | 新增 `require_llm_key_configured` 前置检查（无可用 Key → 400 明确提示） |
| `backend/api/contracts.py` | 4 个触发 LLM 的接口挂上该检查；上传的分类/抽取并行任务改用 `submit_with_context` |
| `backend/ai/{classifier,extractor,matcher,auditor/evidence_extractor}.py` | **仅**把 `ex.map(...)` / `ex.submit(...)` 改为 `submit_with_context(...)`（+1 行 import）——否则线程池里读不到用户 Key |
| `backend/requirements.txt` | 声明 `cryptography`（Fernet 加密依赖） |
| `frontend/src/api/profile.js`（新增） | profile 三个接口封装 |
| `frontend/src/views/ProfileView.vue` | 改为走后端保存/删除；密码型输入；**不再把真实 Key 存 localStorage**（并清理历史遗留）；文案改为"Key 将用于当前账号调用 DeepSeek，不会展示给其他用户" |
| `frontend/src/views/UserManageView.vue` | 用户列表增加「个人 Key：已配置/未配置」列 |
| `backend/tests/test_user_api_key.py`（新增 14 条） | 优先级 / 回退 / 无 Key 报错 / A-B 隔离 / **并发不串 Key** / 删除回退 / API 脱敏 / 中间件绑定 / 前端不存明文 |
| `backend/tests/test_api_key_config.py` | 2 条缺 Key 测试由"import 期报错"改为"调用期报错"（**语义变更，见下**），并新增 1 条"缺 Key 也能 import 启动" |

**新增接口**

```text
GET    /api/auth/profile                  → 个人信息 + deepseek_key_configured（不返回 Key）
PUT    /api/auth/profile/deepseek-key     → 保存当前用户个人 Key（加密落库）
DELETE /api/auth/profile/deepseek-key     → 删除个人 Key（自动回退 .env 默认 Key）
```

**新增表字段**：`users.deepseek_api_key_enc`（TEXT，Fernet 密文；启动自动迁移）

**并发隔离设计（本轮重点）**

* `DeepSeekClient` 不保存 api_key，也不修改任何全局状态 → 不存在"改 singleton 的 key 导致串 Key"
* Key 用 `ContextVar` 按执行上下文隔离；OpenAI client 按 **Key 哈希**缓存（带锁 + 容量上限）
* 绑定放**中间件**（实测：依赖里 set 无效；`ThreadPoolExecutor` 新线程不继承 contextvars，必须 `copy_context`）
* 实测结论：A→KEY_A、B→KEY_B、未配置→DEFAULT_KEY，4 线程 × 200 轮交错无一次串用

**存储**：个人 Key 以 Fernet 加密落库（**非明文**）；前端不保存真实 Key。
局限：安全性等价于 `SECRET_KEY` 强度；轮换 `SECRET_KEY` 会使已存 Key 解不开（按"未配置"回退默认并告警）。

**⚠️ 语义变更（需知悉）**：缺 Key 的报错从 **import 期** 改为 **调用期** —— 否则"`.env` 不配任何 Key、由用户各自配个人 Key"这种部署无法启动。报错内容不变（仍明确指引配置位置、仍不含 Key）。

**验证结果**

```text

A/B 隔离 通过      ｜ 并发隔离（4线程×200轮）通过 ｜ 删除回退 通过
API 脱敏 通过      ｜ 中间件绑定 通过 ｜ 前端 build 通过
原 API Key 测试 7/7 通过 ｜ 全量 backend 173/173 通过
```

**需同步的文档**：`README.md` ✅（Key 两种来源 + 优先级）、`docs/部署与复现.md` ✅（优先级/存储/局限/隔离）
**未触碰**：RAG 检索逻辑、风险判定 R01–R13、证据裁决、推荐规则、Gold、F1、评测口径、DOCX、用户角色权限规则、注册逻辑、数据集、静启动 warmup、bootstrap admin 逻辑
