# 系统架构

> 本文档描述当前 `dev` 分支的**实际实现**，以代码为准（入口 `backend/main.py`、审核主链路 `backend/api/contracts.py::_run_audit`）。不含任何已删除的历史模块（Corex / reporter / Dify / KNN / `audit_with_llm` / 报告导出 / heatmap 端点）。

---

## 一、架构总览（四层）

系统采用经典四层架构，AI 引擎作为**同进程 Python 包**被业务后端直接调用（不走 HTTP）：

```
┌──────────────────────────────────────────────────────────────┐
│ 第一层 前端展示层  Vue 3 + Element Plus + ECharts + pdf.js   │
│   合同上传 / 列表 / 详情 / 审核结果 / 报告 / 模板 / 反馈标注    │
└──────────────────────────────┬───────────────────────────────┘
                               │ Axios (JWT) → REST /api/*
┌──────────────────────────────▼───────────────────────────────┐
│ 第二层 业务后端层  FastAPI + SQLAlchemy                       │
│   认证 / 合同管理 / 审核调度(后台任务 _run_audit) / 模板 / 统计 │
└──────────────────────────────┬───────────────────────────────┘
                               │ 同进程函数调用（非 HTTP）
┌──────────────────────────────▼───────────────────────────────┐
│ 第三层 AI 核心引擎层  ai/ 包                                 │
│   解析 → 分类 → 要素抽取 → 规则召回 → 证据抽取 → 确定性裁决    │
│   → 建议层 → 置信度融合 → 条款定位 → 条款比对                  │
└──────────────────────────────┬───────────────────────────────┘
                               │ SQLAlchemy ORM / 文件读写
┌──────────────────────────────▼───────────────────────────────┐
│ 第四层 数据持久层                                             │
│   SQLite(开发) / MySQL(生产) + ChromaDB(向量库) + 本地文件系统  │
└──────────────────────────────────────────────────────────────┘
```

---

## 二、技术栈

| 层 | 技术选型 |
|---|---|
| 前端 | Vue 3（`<script setup>`）、Element Plus、ECharts、Vite、pdf.js（`pdfjs-dist`）、docx-preview / mammoth |
| 后端 | FastAPI、SQLAlchemy 2.x、Uvicorn、PyJWT、passlib[bcrypt] |
| AI 引擎 | DeepSeek `deepseek-chat`（OpenAI SDK，base_url `https://api.deepseek.com`，temperature 默认 0.1） |
| 向量检索 | ChromaDB（持久化）+ `sentence-transformers`（`shibing624/text2vec-base-chinese`）+ BM25 |
| 文档解析 | `pdfplumber`（PDF）、`python-docx`（DOCX）、PaddleOCR/PaddlePaddle（图片/扫描件 OCR） |
| 数据库 | SQLite（开发）/ MySQL 8.0 + PyMySQL（生产） |

## 三、后端入口与路由

入口 `backend/main.py`（FastAPI app，lifespan 里 `Base.metadata.create_all` + SQLite 安全迁移 + 启动复位遗留 `auditing` 状态），挂载 5 个路由 + 3 个内置端点：

| 路由文件 | 前缀 | 职责 |
|---|---|---|
| `api/auth.py` | `/api` | 注册 / 登录（JWT） |
| `api/contracts.py` | `/api` | 合同上传、列表、详情、审核触发、审核结果、报告、条款比对、修订/审批 |
| `api/feedback.py` | `/api` | 用户反馈标注 |
| `api/templates.py` | `/api` | 模板管理 |
| `api/stats.py` | `/api` | 统计 |
| 内置 | `/api` | `GET /api/health`、`GET /api/contract-types`（读 `ai/taxonomy.py` 唯一真源） |

共享依赖（`api/deps.py`）：`get_db`（数据库会话）、`get_current_user`（JWT 鉴权 + RBAC）。

## 四、AI 引擎模块（`backend/ai/`）

| 模块 | 职责 |
|---|---|
| `taxonomy.py` | 合同分类体系**唯一真源**：11 类法理（8 典型 + 2 无名 + 1 特别法）+ 业务标签「服务外包」 |
| `llm_client.py` | DeepSeek 客户端封装（`deepseek-chat`） |
| `parser/` | `docx_parser.py`（python-docx）、`pdf_parser.py`（pdfplumber）、`ocr_parser.py`（图片/扫描件 OCR） |
| `classifier/` | `rag_classifier.py`（RAG 少样本分类，主）、`classifier.py`（零样本兜底） |
| `extractor/` | `extractor.py`（LLM 抽取四要素：双方/金额/期限/争议解决，分块并行 + 合并） |
| `auditor/` | `rule_engine.py`（规则召回，fast 基线）、`evidence_extractor.py`（LLM 抽事实证据）、`evidence_adjudicator.py`（Python 硬阈值裁决 R01–R12）、`recommendation_engine.py`（建议层 v6.5）；`llm_auditor.py` 为归档脚本（供评测复用，不在生产链路） |
| `matcher/` | `matcher.py`（标准条款比对：覆盖率 / 缺失 / 偏离） |
| `rag/` | `vector_store.py`（ChromaDB + 句向量）、`bm25.py`（BM25 关键词检索）、`init_chroma.py`（向量库初始化）；供 RAG 分类器范本检索 + revise 接口知识检索 |
| `knowledge/` | `laws.json`（法条库）、`risk_cases.json`（风险案例）、`standard_clauses.json`（标准条款集） |
| `chunker.py` | 长文分块 |
| `confidence.py` | 规则/证据等多来源置信度融合 |
| `reviser.py` | 多轮对话式改条款 |

## 五、审核主链路（数据流）

入口 `POST /api/contracts/{id}/audit` → 后台任务 `_run_audit`，顺序如下（详见 [`审核流程.md`](./审核流程.md)）：

```
parsed_text ──(parser)──> 分类(rag_classifier) ──> 要素(extractor)
                              │
                              ▼
规则召回(rule_engine, 始终先跑) ──> 证据抽取(evidence_extractor, LLM抽事实)
                              │              │
                              │              ▼
                              │       确定性裁决(evidence_adjudicator, Python硬阈值 R01–R12)
                              │              │
                              ▼              ▼
                    置信度融合(confidence) + 合并去重
                              │
                              ▼
                    建议层(recommendation_engine, RAG法条+LLM+grounding)
                              │
                              ▼
                    条款定位(_locate_clause) → 入库 AuditRecord
                              │
                              ▼
                    条款比对(matcher) → 报告(AuditReport: 风险表+条款比对)
```

- 审核模式：`precise`（规则 + 证据裁决 + 建议，主口径）/ `fast`（纯规则引擎，确定性基线）。

## 六、数据持久层

**关系型（SQLAlchemy ORM，`backend/models/`）**：`User`、`Contract`、`AuditRecord`、`AuditReport`、`FeedbackLog`、`Template` 六张表。开发用 SQLite（`DATABASE_URL` 指向 `sqlite:///...`），生产切 MySQL（`mysql+pymysql://`）。

**向量库（ChromaDB）**：RAG 检索的范本/法条向量，懒加载，不拖慢启动。

**文件系统**：上传合同原件 + DOCX→PDF 转换副本（`backend/data/`，运行时生成，git 忽略）。

## 七、前端结构

`frontend/src/`：`views/`（登录、首页看板、合同上传、合同列表、合同详情、审核结果、审核结果详情、审核报告、报告详情、模板列表）、`components/`（`RiskBadge` 风险徽章、`FeedbackPanel` 反馈面板）、`api/`（按模块封装的 Axios 请求 + JWT 拦截）、`router/`、`composables/`、`constants/`、`utils/`。详见 [`项目目录说明.md`](./项目目录说明.md)。

## 八、关键设计决策

1. **证据-裁决解耦（v6.4）**：LLM 只抽取条款客观事实证据，风险判定由 Python 按硬阈值裁决，保证可复现、同模板一致。
2. **建议层后置（v6.5）**：只消费裁决结果、只负责「怎么改」，不反向影响 R01–R12 判定；法条依据按编号在 `laws.json` 精确查表（不做向量语义检索，避免语义漂移）。
3. **规则召回始终先跑**：既是 `fast` 基线，也是 `precise` 异常时的兜底。
4. **分类体系唯一真源**：`ai/taxonomy.py`，分类器/条款比对/前端下拉共用，不各写一份硬编码。
