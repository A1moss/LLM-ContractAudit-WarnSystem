## 一、核心口径（一句话）

**一条条款标为风险，当且仅当：它有明确法条依据，或对一方造成实质不利。模棱两可的不标。**

判定顺序（逐条问自己）：

1. 这条对某方（多为弱势方/委托方）**会造成实际损失或维权困难**吗？——是 → 标
2. 能找到**法条依据**吗（民法典 585/590/496/497/859 等、劳动法、个保法、招标投标法）？——能 → 标
3. 只是"写法不规范/措辞模糊但没有实质损害后果"？——是 → **不标**
4. 双方权利义务对等、行业惯例如此、无单方优势？——**不标**

**"实质不利"操作化定义**：让一方**承担超出正常商业对价的成本、风险或责任**——具体包括：
- 责任无上限/无边界（全部损失、一切责任）
- 权利单方化（一方可随时解约/调价/改约，另一方无对等权利）
- 成本转嫁（违约金远超损失、预付款远超履约进度、无限保密/竞业义务）
- 维权通道受损（管辖在对方所在地、无客观验收机制、无不可抗力免责、自动续约无退出机制）

> 示例（标 vs 不标）：
> - "违约金按合同总金额的 30% 计算，不足部分另行赔偿" → **标**（R01，民法典 585 违约金可调减）
> - "双方应按合同约定履行各自义务" → 不标（无实质不利）
> - "付款方式：验收合格后 30 日内一次性支付" → 不标（对等合理）
> - "委托开发成果归甲方，甲方支付 1300 万开发费，乙方保留背景 IP" → 不标（有对价买断，民法典 859 条任意性规则）

## 一·补、三条上位规则（v1.2.3，AI 法理审核定夺固化）

> 以下三条规则优先级高于各风险类型的具体判定，所有"公告 vs 披露版"冲突均按此处理。

### 规则 A：风险存在性看披露版正文

**风险有没有，看披露版合同文本实际写了什么。公告仅用于校验，不用于无依据地补足披露版缺失内容。**

- 公告、招标文件或其他外部材料存在验收标准/不可抗力/争议解决等条款，但披露版未明确援引、纳入或体现的，**不得据此认定披露版已经具备该机制**。
- 只有当披露版明确写"按照《技术规格书》第 X 条执行，该技术规格书为本合同附件"时，才可认为正文明确纳入了外部标准。
- 适用：R08（验收机制）、R09（不可抗力）、R04（争议解决）等所有"缺失型"风险。

### 规则 B：数值型风险严格按阈值

**数值型风险（如违约金比例）严格按本清单明确约定的阈值判断，不得以"年化后很高""累计后超线"等方式变相扩大阈值。**

- R01 阈值：日 **5‰**（千分之五）。3‰/日即使年化 109.5% 也不触发 R01。
- 阈值以下但确实偏高的条款，可进 business_risks 提示"违约金偏高但未达 R01 阈值"，不进严格 F1 分母。

### 规则 C：披露版与公告冲突分别记录

**披露版与公告存在实质性冲突时，分别记录"披露版风险"和"公告—披露版不一致"，不以公告内容直接覆盖披露版风险。**

- 披露版写了一个不利条款（如自动顺延 3 年），即使公告写的是另一种更合理的安排（如主动续约+书面确认），披露版的风险仍照标。
- 同时在 business_risks 中记录"披露版—公告 XX 条款重大不一致"，说明两者的具体差异。
- 适用：R11（自动续约）、R04（争议解决）、金额/期限等所有可能出现公告与披露版不一致的字段。

## 二、风险类型法理描述（盲标参考）

> 以下只给**法理含义**，不给触发词/正则，标注时按"这条约定是否构成该风险"判断，不看字面写法。

| 类型 | 法理含义（v1.2 修订） | 典型情形示例 | 依据参考 |
|---|---|---|---|
| R01 违约金过高 | 违约金明显超过实际损失，法院可调减 | 日 1% 累计超 20%、上不封顶、日 5% | 民法典 585 |
| R02 无限责任 | 赔偿责任无上限/覆盖一切损失 | "全部损失""一切责任""任何损失""含预期利益/间接损失" | 民法典 584（可预见规则） |
| R03 单方解约权 | 一方可随时无理由解约且无补偿（含委托/承揽任意解除权） | 甲方有权随时终止、无需补偿；委托人/定作人任意解除未补偿 | 民法典 562/563/933/787 |
| R04 管辖不利 | 管辖法院/仲裁地**明确偏向对方**（我方=甲方）。**v1.2.2 细化**：①"异地"不等于"偏向对方"，必须能识别出约定的法院管辖地/仲裁地具有明确的对方地域偏向；②不能仅根据仲裁机构所在地进行推定（如"深圳国际仲裁院"≠"仲裁地在深圳且偏向对方"）；③"争议解决条款冲突（同时约定法院+仲裁）"不构成 R04，应进 business_risks 提示条款效力不确定性。**v1.2.3 固化**：R04 判断披露版实际约定的争议解决地点/机构是否偏向对方；公告中与披露版冲突的另一套争议解决安排，不用于反向触发 R04，但应单独作为文本不一致问题记录（business_risks） | 由乙方所在地/对方所在地法院管辖；明确约定仲裁地在对方所在地 | 民诉法 35 |
| R05 保密期不合理 | 保密义务永久/无限期，无合理边界 | "永久保密""无限期" | 民法典 501、商业秘密司法解释 |
| **R06 IP 权益失衡** | **无对价/明显不对称的成果利益剥夺**（非"成果归甲方就标"） | 合作开发双方投入对等但甲方独占全部收益且乙方无合理补偿；乙方已有核心技术被无偿转走；要求乙方未来改进技术无偿转让 | **民法典 859**（委托开发专利申请权，任意性规则，当事人另有约定除外）、860-864 |
| R07 付款义务失衡 | 付款义务与服务贡献明显脱钩，或期限/范围明显失衡（不机械按年限） | 预付 80%、验收后拒不支付尾款；居间尾随期覆盖范围过宽且与居间服务无因果关系 | 民法典 525/526、965 |
| **R08 验收机制缺失** | **缺乏足以客观判断交付是否合格的验收机制**（区分"机制缺失"与"标准不完整"）。**v1.2.2 细化**：①有"验收/点验/检查"字样不等于有验收机制，仅有"验收合格后付款"这类结果性表述而无明确标准/程序/责任主体的，标 R08；②外部存在国家标准不当然补足验收机制，除非合同明确援引并纳入合同组成部分；③"质量争议时第三方鉴定"属争议处理机制，不能倒推为日常交付验收机制；④只有当文本能够通过明确标准、程序、责任主体或明确援引并纳入合同的外部验收文件，使交付是否合格具有客观可判断性时，才不标 R08 | 完全没有验收节点/程序/后果；只有"验收合格后付款"一句话无任何判断依据；仅有"点验/检查合格"但无标准/程序/责任主体 | 民法典 621-623、**845**（技术合同应含验收标准和方法） |
| R09 不可抗力缺失 | 交付型商业合同无不可抗力条款，免责无据 | 未约定不可抗力处理（仅交付型合同标） | 民法典 180/590 |
| **R10 竞业限制过宽** | 竞业范围/地域/期限超出合理限度（商业竞业开口子：≥5 年+全国/主营全禁才标） | 全国范围、所有行业、5 年+全行业禁入 | 劳动合同法 23/24（劳动竞业）、商业惯例（商业竞业） |
| **R11 自动续约陷阱** | 期满自动续，无书面退出机制（强弱区分：有退出通道=弱，无上限=强） | "期满未提出异议自动续期一年""顺延至交易结束（无上限）" | 民法典 734（租赁）类推 |
| R12 数据隐私不当 | 数据/个人信息共享、提供、转让无授权边界 | 客户数据可共享给第三方、研发体系内共享无脱敏 | 个保法 13/23、民法典 1035 |
| R13 名实不符 | 名义类型与实质法律关系不一致 | 名为服务外包实为劳务派遣 | 劳动合同法 66、劳务派遣暂行规定 |

**R04 视角规则（v1.2 定标）**：统一"我方=甲方"——R04 = 管辖在乙方（对方）所在地；甲方/委托方/披露方/原告所在地 = 不标（与规则引擎 R04 正则一致，简单可复现）。

**R06 关键区分（v1.2 定标）**：
- 委托开发：甲方支付明确对价（开发费）+ 项目成果归甲方 + 乙方保留背景 IP → **不标 R06**（标准买断结构，民法典 859 条任意性规则允许约定）
- 合作开发：双方投入对等但甲方独占全部收益、乙方仅学术使用且无商业权利 → **标 R06**（无对价收益独占）
- 承揽：承揽人利用定作人技术资料完成的改进成果 + 未支付费用的开发成果 IP 均无偿归定作人 → **标 R06**（智力成果无偿剥夺）

**R06 乙方保留权利边界（v1.2.4，AI 法理审核裁决固化，047 边界样本）**：
- "IP 归甲方所有"本身不等于所有相关权利都不存在；只有当乙方保留的复制/使用/许可/商业化等权利达到**实质削弱甲方的排他控制或商业化权益**的程度，才突破"买断不标"规则。
- "乙方仅保留代码复制权" → **通常不标 R06**（残余权利安排，不改变 IP 所有权归属，047 案例）
- 若变成"乙方可自由复制/修改/许可/向第三方商业化使用/再开发" → **才重新标 R06**（甲方排他权益被严重削弱）
- 核心判断：合同类型优先于成果载体判断（047 有"论文"成果但仍是技术开发交付型合同，不影响 R09 判断）

**R08 关键区分（v1.2 定标）**：
- 有完整验收机制（阶段验收+最终验收+宽限期+验收失败终止权/扣款）但缺技术指标 → **不标 R08**（属"验收标准不完整"提示，进 business_risks）
- 只有"验收合格后付款"一句话，无验收程序/标准/后果 → **标 R08**（缺乏客观验收判断机制）
- 完全没有验收相关表述 → **标 R08**

**R09 非交付型不标（v1.2 定标）**：租赁/中介/委托/框架协议/物业服务等非交付型合同，行业惯例本就不写不可抗力条款 → 缺失不标 R09。仅交付型合同（买卖/承揽/建设/技术开发）缺失标 R09。劳动合同、保密协议不适用 R08/R09。

**R10 商业竞业开口子（v1.2 定标）**：
- 劳动竞业（劳动合同法 23/24）：超 2 年、超原经营范围/地域 → 标
- 商业竞业（非劳动关系）：期限 ≥5 年 **且** 范围全国/主营业务全禁 → 标；3 年同类项目排他 → 不标

**R13 特例**：只标"名义 vs 实质"背离的（正文同时有名义信号与实质信号）。纯劳务派遣、劳动合同期限等**不标 R13**（转 business_risks 或按对应类型标）。R13 定位=规则信号示警、单列报告、不进严格 F1。

## 三、缺失型风险标注规则（R08/R09 关键）

- **R08/R09 缺失基准按合同类型定（v1.2 修订）**，不搞一刀切：
  - 必有验收机制的类型：买卖/采购、承揽、建设工程、技术开发（交付成果类）→ 缺失标 R08
  - 未必有验收条款的类型：委托/中介（按成果/报酬结算）、租赁、物业/服务（按服务期考核）→ **缺失不自动标 R08**，除非正文明确有验收义务却无机制
  - 不可抗力条款：仅交付型商业合同（买卖/承揽/建设/技术）通常必备 → 缺失标 R09
  - 非交付型（租赁/中介/委托/框架/物业）+ 劳动合同 + 保密协议 → **不标 R09**
- **补全版定位区分**：补全版 md 定位 = **已补全的完整合同**→
  - 某条款在公告原文已披露 → 按披露内容判断
  - 未披露且补全未覆盖 → 按"完整合同缺失"标缺失型风险，desc 注明「补全版未含该条款」
  - 例外：确属"公告摘要省略、与合同风险无关"的表述（如业务背景介绍）不标
- 判断标准：**同类型合同通常必有、缺失会导致维权无据**的条款才标缺失型；非必备的缺失不标

## 四、各类型合同重点检查项（盲标时按此逐项过）

| 合同类型 | 必查风险点 |
|---|---|
| 买卖/采购 | 违约金、质量验收、付款条件、无限责任、管辖、不可抗力 |
| 租赁 | 自动续约、违约金、维修责任、押金退还、管辖（R09 不标） |
| 建设/施工 | 工期违约金、付款节点、无限责任、验收、质保金、不可抗力 |
| 技术开发/服务 | IP 归属（有对价买断不标 R06）、保密期、数据隐私、验收机制、无限责任、不可抗力 |
| 物业/服务 | 服务标准、违约责任、自动续约、费用调整（R09 不标） |
| 委托/中介 | 报酬与付款、无限责任、单方解约、保密、自动续约（R09 不标） |
| 劳动合同 | 竞业过宽、服务期违约金、派遣三性（R13 例外）、保密期（R09 不标） |
| 保密协议 | 保密期限不合理、竞业过宽、无限责任（R08/R09 不适用） |
| 无名/混合 | 按实质条款逐项过上述所有项（R09 视是否交付型定） |

## 五、标注格式（进 realtest.json risks）

每条标注 = `{risk_type: "R0X", desc: "一句话说明：条款要点 + 为什么是风险"}`

```json
{"risk_type": "R01", "desc": "违约金按合同总价30%计算且不足部分另行赔偿，超出实际损失可调减（民法典585）"}
{"risk_type": "R08", "desc": "补全版仅「验收合格后付款」，无验收标准与程序，交付质量争议无客观判断依据（民法典845）"}
```

- 每份合同标注条数不限，**全量标**（不限于 1-2 条）
- desc 必须含**条款要点**（可定位）——这是 span 级可复核的基础
- 同一条款同时触发多类风险的，**分别标注**
- 不进严格 F1 的提示项（如"验收标准不完整""尾随期偏长"）→ 进 `business_risks` 字段，不进 `risks`

## 六、一致性保障（双人背对背）

1. 每批抽 10 份（覆盖 6+ 类型，含补全版与真实版）双人独立标注
2. **一致性指标**：不用简单一致百分比——改用：
   - **Cohen's Kappa**（主指标，排除偶然一致）
   - 或 **双人互当金标准算 F1**（A 标 B 的 P/R/F1 + B 标 A 的 P/R/F1，取均值）
   - 目标：Kappa ≥ 0.6 或 F1 ≥ 0.7
3. **"待议"兜底**：拿不准的案例**先标"待议"**，讨论后定标——不各自硬判
4. 不一致的逐条讨论定标 → 定标结果写回 gold，并记入标注日志
5. 跨批一致性检查：新批次定标时必须回溯已落库的同类型合同，确保同类条款标注一致（如 051/052 R08 统一）
