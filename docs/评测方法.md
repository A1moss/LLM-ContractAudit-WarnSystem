# 评测方法

> 三套正式评测的脚本、输入、计算公式与冻结指标。公式以 `backend/evaluate/` 下脚本实际实现为准。**冻结指标与本口径不得改动。**

---

## 一、总览

| 评测 | 脚本 | 输入测试集 | 正式指标（冻结） |
|---|---|---|---|
| 法理分类 | `evaluate_rag.py` | `classification_test.json`（147 份） | **98.6%**（145/147） |
| 要素抽取 | `evaluate_elements.py` | `realtest.json`（84 份） | **93.7%**（披露样本加权综合 F1） |
| 风险识别 | `evaluate_evidence.py` | `realtest.json` + `evidence.json`（84 份） | **P 76.6% / R 80.1% / F1 78.3%** |

评测均走 DeepSeek `deepseek-chat`；分类 temperature=0.1，要素/证据 temperature=0.0。分类与要素结果有 md5 缓存（`cache_elements.json` / `rag_predictions.json`），可复跑。

---

## 二、分类评测（`evaluate_rag.py`）

- **输入**：`classification_test.json`（147 份 = 84 第一批 + 55 第二批 + 8 人工边界样本；正文已去除「法理类型」等答案元信息，Gold 冻结）。
- **流程**：对每份调用 `classify_by_rag(body, top_k=3)`（RAG 少样本分类：检索 top-K 相似范本作示例喂 LLM，temperature=0.1）；预测 `contract_type` 与 `true_type` 比对。
- **指标**：
  - 准确率 `acc = 正确数 / 总数`
  - 每类 P/R/F1（`precision = 该类预测正确的样本数 / 预测为该类的样本数`，`recall = 该类预测正确 / 该类真实样本数`）
- **输出**：准确率 + 每类 P/R/F1 + 判错样本 + 预测快照 `rag_predictions.json`。
- **正式口径**：**98.6%（145/147，判错 2：技术 1 + 劳动 1）**。历史口径 97.62%（82/84，84 份原测试集）保留作版本对照。

> 注：分类 temperature=0.1 存在 145↔147 的轻微波动，正式口径**冻结在 98.6%（145/147）**，不因单次运行到 146/147 而改写。

## 三、要素评测（`evaluate_elements.py`）

- **输入**：`realtest.json`（84 份）；对每份调 `extract_elements` 抽取四要素：`parties`（双方）、`amount`（金额）、`performance_period`（期限）、`dispute_resolution`（争议解决）。
- **比对口径**：只统计 gold 中 `present=true`（公告实际披露）的要素，做**值级严格比对**（金额 10% 容差、期限年份交集、争议关键词匹配）。
- **单要素指标**：对每个字段在其「披露样本」上算 TP/FP/FN → P/R/F1。注：`pred` 非空但比对不命中（抽到但值错）时**同时计入 FP 与 FN**，故精确率分母 = tp+fp、召回率分母 = 披露样本数，两者不同（严格 F1 的刻意设计）。
- **披露样本加权综合 F1**（非标准宏平均，按各字段披露样本数加权、用加权 P/R 反推）：

  ```
  w_p = Σ(field_p × field披露样本数) / Σ(field披露样本数)
  w_r = Σ(field_r × field披露样本数) / Σ(field披露样本数)
  w_f = 2 · w_p · w_r / (w_p + w_r)
  ```

- **正式口径（冻结）**：

  | 要素 | 披露样本 | F1 |
  |---|---|---|
  | 双方 | 84/84 | 100.0% |
  | 金额 | 78/84 | 87.2% |
  | 期限 | 82/84 | 90.8% |
  | 争议解决 | 84/84 | 96.3% |
  | **综合** | — | **93.7%** |

> 公告型样本的期限/争议披露率 <100%，严格 F1 仅在披露样本上计算；完整合同 + span 级标注后披露率与 F1 才能对齐赛题硬指标。

## 四、风险评测（`evaluate_evidence.py`）

- **输入**：`realtest.json`（84 份）+ `evidence.json`（`run_evidence.py` 预计算的 LLM 证据抽取结果）。
- **裁决**：与生产共用同一裁决函数 `ai.auditor.evidence_adjudicator.adjudicate_risks`（v6.4，只裁决 **R01–R12**），消除历史内置复制版，避免口径错位。
- **比对**：逐份合同把 `gold risks 集合 G` 与 `pred 集合 P`（均限 R01–R12）做集合比对：

  ```
  TP = Σ|G ∩ P|   （gold 且预测正确）
  FP = Σ|P \ G|   （多报）
  FN = Σ|G \ P|   （漏报）
  P = TP / (TP + FP)
  R = TP / (TP + FN)
  F1 = 2·P·R / (P + R)
  ```

- **正式口径（冻结）**：**P 76.6% / R 80.1% / F1 78.3%（TP 121 / FP 37 / FN 30）**。

### R13 与双引擎（`evaluate_risks.py`）

- `evaluate_risks.py` 为**双引擎六列**评测（fast 规则引擎 / precise 规则+LLM），其中 **R13「疑似名实不符」单列示警，不进严格 F1**。
- 正式风险指标以 `evaluate_evidence.py` 的证据-裁决口径为准（R01–R12）。
