# 审核流程说明

> 审核流水线入口：`backend/api/contracts.py::trigger_audit` → 后台任务 `_run_audit`
> 审核模式：`precise`（规则+LLM，主口径）/ `fast`（纯规则引擎，确定性基线）

---

## 一、流水线总览

```
上传合同
  │
  ├─ 1. 文档解析   parser/        → parsed_text（docx / pdf / ocr）
  ├─ 2. 法理分类   classifier/    → contract_type（11类）+ is_outsourcing
  ├─ 3. 要素抽取   extractor/     → elements（双方/金额/期限/争议解决）
  │
  ├─ 4. 规则召回   rule_engine.py → fast 基线（确定性正则，始终先跑）
  │
  ├─ 5. 证据抽取   evidence_extractor.py → LLM 只抽事实证据（precise）
  ├─ 6. 确定性裁决 evidence_adjudicator.py → Python 硬阈值裁决 R01–R12（v6.4 冻结）
  ├─ 7. 建议层     recommendation_engine.py → RAG 法条 + LLM 建议 + grounding（v6.5）
  │
  ├─ 8. 置信度融合 enrich_confidences → 规则/LLM 等多来源交叉验证上调
  ├─ 9. 条款定位    _locate_clause → 定位条款位置 → 入库 AuditRecord
  ├─ 10. 条款比对  matcher/        → 标准条款覆盖率 + 缺失/偏离
  └─ 11. 报告生成  contracts.py    → AuditReport（风险表 + 条款比对章节）
```

---

## 二、逐步说明

### 1. 文档解析（`ai/parser/`）
`docx_parser.py` / `pdf_parser.py` / `ocr_parser.py` 把上传的合同文件转成纯文本 `parsed_text`，供后续所有环节使用。

### 2. 法理分类（`ai/classifier/rag_classifier.py`）
RAG 少样本分类——先在合同范本向量库检索 top-K 篇最相似已标注范本作「少样本示例」，再喂 LLM 参照范本推理，输出 11 类法理类型之一（买卖/租赁/承揽/建设工程/技术/委托/物业服务/中介/保密协议/无名/劳动合同）+ `is_outsourcing`（是否外包）；检索无结果时降级纯 LLM 零样本。分类体系唯一真源在 `ai/taxonomy.py`。实测准确率 **98.6%**（145/147，147 份分类正式测试集；历史口径 97.62%，82/84）。

### 3. 要素抽取（`ai/extractor/extractor.py`）
LLM 抽取四要素：双方、金额、期限、争议解决，Pydantic 校验，分块并行。实测披露样本加权综合 F1 **93.7%**。

### 4. 规则召回（`ai/auditor/rule_engine.py`）
`RISK_RULES` + `RULE_LAWS`，确定性正则召回，作为 `fast` 基线**始终先跑**，也是 `precise` 模式异常时的兜底。

### 5. 证据抽取（`ai/auditor/evidence_extractor.py`）—— v6.4 核心
LLM 只做一件事：**抽事实**，不做风险判断。按 v6.2 schema 输出每条条款的数值/范围/管辖地/验收机制等结构化证据；补全风险条款走 `_split_supplement` 独立输入；长文分块并行 `_extract_chunk`。

### 6. 确定性裁决（`ai/auditor/evidence_adjudicator.py`）—— v6.4 核心
Python 按 v1.2.4 口径的**硬阈值**裁决 R01–R12（如 R01 日 5‰、R10 竞业 ≥5 年 + 全国/主营全禁）。**风险判定零 LLM 自由发挥**，保证可复现、同模板一致。此层已冻结，评测口径不得改动。

### 7. 建议层（`ai/auditor/recommendation_engine.py`）—— v6.5
只消费裁决结果，不反向影响 R01–R12 判定：
- **RAG**：按法条编号精确取条文（`ai/knowledge/laws.json`），不做语义检索（避免语义漂移）；
- **LLM**：生成修改建议（怎么改），重试 2 次 + 空建议兜底到 guardrail 方向；
- **grounding**：校验建议不编造数字/法条（含中文数字）。

### 8. 置信度融合（`ai/confidence.py`）
规则 / LLM 等不同检测来源独立检出同一风险时交叉验证上调置信度。

### 9. 条款定位 + 入库（`_locate_clause`）
定位风险条款在合同中的位置（第几条 + 标题），连同 evidence、recommendation 写入 `AuditRecord`。重新审核时先删旧记录，避免新旧批次混杂。

### 10. 条款比对（`ai/matcher/matcher.py`）
对照 `ai/knowledge/standard_clauses.json` 标准条款集，输出覆盖率、缺失条款、偏离说明、补全建议。失败不阻断风险审核，报告标注「待重试」。

### 11. 报告生成（`contracts.py`）
风险等级统计（high/mid/low）、风险评分、HTML 报告（风险表 + 条款比对章节）、热力图数据，写入 `AuditReport`。

## 三、两个审核模式

| 模式 | 路径 | 用途 |
|---|---|---|
| `fast` | 仅步骤 4（规则引擎） | 确定性基线，秒级出结果 |
| `precise` | 步骤 4–7 全量（规则+证据+裁决+建议） | 主口径，精准率/召回率达标 |

> 前端与后端默认值均为 `precise`（历史教训：默认 `fast` 会输出纯规则的垃圾结果，已三处统一）。

## 四、核心设计原则（数据验证过的经验）

1. **LLM 布尔/数值稳，复杂枚举/嵌套数组崩** → 复杂结构化输出交给代码裁决，不交给 LLM。
2. **关键词匹配 > LLM 分类** → R02 无限责任用 scope/absolute_text 关键词匹配，不用 LLM 分类。
3. **建议层不编数字** → grounding 检查 + prompt 禁编示例数字。
4. **RAG 按法条编号精确取，不语义检索** → 避免 R11→无固定期限、R12→技术秘密这类语义漂移。
