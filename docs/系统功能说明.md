# 系统功能说明

> 面向**使用者、评审与开发人员**：逐页说明系统当前真正实现的功能、操作路径、后端接口，以及每个功能的真实边界。
> 前端代码位置以 `frontend/src/` 为基准，后端接口以 `backend/api/` 为基准。**本文不含任何未实现的规划功能。**

---

## 一、角色与可用范围

系统有 4 个角色（`api/deps.py`）：`uploader`（上传者）/ `reviewer`（审核人）/ `approver`（验收人）/ `admin`（管理员）。

- **公开注册只能得到 `uploader`**（注册接口不接受 `role` 字段）；其余角色由管理员在「用户管理」页分配；
- 前端的菜单与按钮按 `localStorage.role` 显隐，但**权限的权威判定完全在服务端**（`require_role` 读取数据库中的真实角色）。伪造 token 中的 role 无效；
- **uploader 只能看到自己上传的合同**；reviewer / approver / admin 可见公司范围全部合同；已删除的合同对所有人不可见。

## 二、页面与路由总览

路由定义在 `frontend/src/router/index.js`（history 模式，全部懒加载）：

| # | 路径 | 页面组件 | 说明 |
|---|---|---|---|
| 1 | `/` | `HomeView.vue` | 首页：Hero、KPI、核心能力、最近合同 |
| 2 | `/login` | `LoginView.vue` | 登录 / 注册 + 游客模式开关 |
| 3 | `/contracts/upload` | `ContractUpload.vue` | 合同上传（需登录） |
| 4 | `/contracts` | `ContractList.vue` | 合同列表 |
| 5 | `/contracts/:id` | `ContractDetail.vue` | **合同详情工作台**（5 个 Tab，需登录） |
| 6 | `/audit/result` | `AuditResult.vue` | 审核历史（列表 + 内联明细） |
| 7 | `/audit/result/:contractId` | `AuditResultDetail.vue` | 单合同风险明细 |
| 8 | `/audit/report` | `AuditReport.vue` | 审核报告列表（含内联预览图表） |
| 9 | `/audit/report/:contractId` | `AuditReportDetail.vue` | **独立完整审核报告** |
| 10 | `/templates` | `TemplateList.vue` | 标准条款模板管理 |
| 11 | `/profile` | `ProfileView.vue` | 个人信息 + DeepSeek Key |
| 12 | `/users` | `UserManageView.vue` | 用户管理（管理员） |
| 13 | `/:pathMatch(.*)*` | `NotFoundView.vue` | 404 |

**路由守卫**（唯一的守卫逻辑）：

- 有 token → 放行；访问 `/login` 时跳回首页；
- 无 token + 游客模式开启（`localStorage.guest_mode !== 'false'`，**默认开启**）→ 仅放行无 `requiresAuth` 的路由（首页、登录、合同列表、404）；
- 无 token + 游客模式关闭 → 除 `/login` 外一律跳登录。

**路由层没有任何角色判断**。角色相关的显隐逻辑分布在 `App.vue`（菜单）、`useContractWorkspace.js`（`canReview` / `canApprove` / `canUpload`）、`ContractList.vue`（删除按钮）、`UserManageView.vue`（提示条），全部基于 `localStorage.role`，**仅供 UI 提示**。

> 已知细节：`/contracts`（合同列表）**没有** `requiresAuth`，因此游客模式下可打开页面，但列表接口需要登录，页面会显示错误而非数据。

## 三、合同上传

**页面**：`ContractUpload.vue` → `POST /api/contracts/upload`（`multipart/form-data`）

| 项 | 实际取值 |
|---|---|
| 支持格式 | `.docx` / `.pdf` / `.jpg` / `.jpeg` / `.png` / `.tiff` / `.tif` / `.bmp` |
| 表单字段 | `file`、`name`（可选）、`contract_type`（可选，手选时跳过分类）、`audit_mode`（`precise` 默认 / `fast`） |
| 权限 | `require_role("uploader")` —— reviewer / approver 返回 403 |
| LLM 前置 | `require_llm_key_configured` —— 无可用 Key 时返回 400 并提示去「个人信息」页配置 |

上传时后端**同步**完成：解析/OCR → 分类 → 要素抽取（分类与要素抽取并行），写入 `contracts`（`status = "parsed"`）后返回合同 id。

**真实边界**：

- 扫描版 PDF 无文字层、或图片未识别到文字时返回 422 并给出明确提示（**不会**生成一份空合同）；
- 分类与要素抽取依赖 LLM；分类失败回退 `contract_type = "other"`，要素抽取失败使用空要素（均记 warning，不阻断上传）；
- 上传阶段**不产生任何风险结论**，风险在触发审核后才产生。

## 四、合同列表

**页面**：`ContractList.vue` → `GET /api/contracts`

- 分页（`page` / `page_size`，每页最多 100）、关键词（按文件名）、合同类型、状态筛选；
- 每行显示：文件名、法理类型 + 业务标签（如「承揽合同（服务外包）」）、状态、类型置信度、**风险总数与高/中/低计数**（后端一次聚合查询返回，避免前端 N+1）；
- 操作：「查看详情」「审核结果」「删除」；
- **删除**是**软删除**（`status = "deleted"`），并把落盘文件归档到 `backend/data/deleted/`；权限为「admin 任意 / uploader 仅自己的」。

## 五、合同详情工作台（`/contracts/:id`）—— 系统主界面

`ContractDetail.vue` 自身只是页面壳（约 200 行），**全部状态与逻辑集中在 `composables/useContractWorkspace.js`**，子组件只消费同一个 `ws` 对象。`composables/workspaceLogic.js` 存放可被 node 直接测试的纯逻辑。

顶部信息条：文件名、状态标签、「服务外包」标签、`#id`、法理类型、上传时间、审核方式（精细审核 / 快速初筛）。右侧按状态与角色条件出现「复核通过 / 驳回重审」（reviewer）与「验收通过」（approver）。

**5 个一级 Tab**（`constants/navigation.js` 的 `PANE` 是权威常量）：

| Tab 标签 | pane 名 | 子组件 | 内容 |
|---|---|---|---|
| **原始文本** | `text` | `OriginalTextPanel.vue` | 条款导航、正文、搜索、风险标注 |
| **风险详情** | `audit` | `RiskPanel.vue` | 风险统计、筛选、风险卡、反馈面板 |
| **条款比对** | `compare` | `ComparisonPanel.vue` | 缺失/偏离/已覆盖三组 |
| **修改合同** | `revise` | `RevisionWorkbench.vue` | 三栏修改工作台 |
| **审核报告** | `report` | `ReportPanel.vue` | 审核结果驾驶舱 |

**默认 Tab 是「原始文本」**。

> **命名陷阱（代码中明确记录）**：query 取值 `?tab=audit` 指的是**「审核报告」Tab**（内部 pane 名是 `report`），而内部 pane 名 `audit` 指的是**「风险详情」Tab**。二者同名不同义，只允许通过 `paneFromQueryTab()` 翻译，页面代码不得直接拿 query 值当 pane 名用。

### 5.1 原始文本 Tab（`OriginalTextPanel.vue`）

- 左栏**条款导航**：`第X条 <标题>` 列表（来自 `_parse_headings` 口径的标题结构），无标题结构时提示「未识别到「第X条 / X、」标题结构」；
- 正文按行渲染，支持**关键词搜索**（回车定位下一个、「上一个 / 下一个」、`n / N` 计数、当前命中高亮）；
- **风险标注**开关：把审核阶段已定位的风险在正文中以可点击高亮标出（按等级着色），点击 → 切到「风险详情」并定位到该风险卡；
- 顶部提示条如实说明：**有 K 条风险在审核阶段未建立可靠原文锚点，因此不在正文中标注位置（不伪造位置）**；
- 「下载原始文件查看」按钮 → `GET /api/contracts/{id}/file`；
- **本面板除「下载原始文件」外不调用任何额外接口**，正文与标注位置全部来自 workspace 已加载的数据（`parsed_text`、`headings`、`riskRanges`）。

### 5.2 风险详情 Tab（`RiskPanel.vue`）

- 统计条：当前审核风险数、高风险、中风险、低风险、修改会话总数；
- 「开始审核 / 重新审核」→ `POST /api/contracts/{id}/audit` + 前端轮询（2s 间隔，最长 180s）；
- **筛选器**：风险等级、风险规则（`Rxx · 中文名`）、**定位状态**（已自动定位 / 可定位（预检）/ 未定位）、**修改状态**（未修改 / 已修改）、关键词；
- 每张风险卡：等级标签、R 编号、中文风险名、定位状态与条款号（`已自动定位` / `已定位 第X条` / `预检可定位（待后端确认）` / `未定位`）、修改轮次（`已修改 N 轮` / `未修改`）、置信度、检测方式、条款原文、判定理由与修改建议摘要；
- 按钮：「去修改合同」/「去修改合同 · 需指定位置」/「展开详情」；
- **展开详情**含 5 个区块：原文证据（锚点原文 / 位置 / 字符区间 / 证据来源 / 命中法条 / 知识库引用 / 一致度）、判定理由、修改建议、**建议层**（风险说明 / 修改示例 / 法律依据 / 接地检查结果）、**记录元信息**（审核批次 / 结果状态 / 反馈状态）；
- 底部 `FeedbackPanel`：**确认 / 修正 / 误报 / 补充 / 撤销**，并提供明确的披露文案「该反馈已进入反馈池；需经审核 + 管理员批准后才可能用于持续优化（不会立即生效）」；
- 审核被驳回时显示 `上次审核已被驳回，以下为已驳回的历史结果`（依据后端 `has_current_result`，不靠合同状态推导）。

> **本面板没有「上一项 / 下一项风险」导航**；风险间的连续浏览只在「独立完整审核报告」页提供。

### 5.3 条款比对 Tab（`ComparisonPanel.vue`）

- 指标条：条款覆盖率、比对标准条款数、已覆盖、部分偏离、缺失；
- 三组列表：
  - **缺失条款**（提示「该条款在标准范本中存在，本合同中缺失 → 走「新增条款」」），每行有「新增条款」按钮；
  - **存在偏离**（partial，或 covered 但确有偏离/补全建议 → 走「修改条款」），每行有「修改条款」按钮；
  - **已覆盖（无偏离）**；
- 「缺失关键条款」红色标签；「跨条款关联风险（后端图分析）」区块（前置依赖缺失 / 条款互斥冲突）；
- 「刷新比对结果」/「重新比对」按钮；
- 接口：`GET /api/contracts/{id}/clause-comparison`（无缓存时后端当场生成，超时设为 **300 秒**，因为含同步 LLM 调用）；
- 状态说明：后端对「未生成 / 生成失败 / 无正文」都会返回空结果，三者不可区分，因此界面用统一的提示 + 「重新比对」引导；
- 页脚如实说明：比对接口**不返回标准条款正文**，所以这里只展示条款名与优先级。

### 5.4 修改合同 Tab（`RevisionWorkbench.vue`）

三栏工作台：**左栏会话导航（约 240px）｜中栏当前会话对话｜右栏合同工作区（约 420px）**，底部固定「下载状态条」。

详见 [`条款修改与修订机制.md`](./条款修改与修订机制.md)。此处只列功能面：

- 左栏统计：待处理风险 / 条款比对问题 / 已确认修改；5 个会话分组：**总体修改、待处理风险、条款比对、新增条款、历史修改**；
- 中栏：逐轮展示「你的要求」与「AI 修改建议」（含约束、依据、插入位置、剩余风险），每轮可「查看此版对比」「复制修改稿」；已采用的轮次显示「已采用」标签；
- 右栏按会话状态切换：总体会话 → 总控台；历史会话 → 只读；已定位 → 当前位置 + 差异对比 + 依据 + 剩余风险 + **「确认采用此版」/「继续调整」**；未定位 → 定位面板（按条款号 / 搜索原文 / 描述位置）+ 「新增条款」入口；新增条款会话 → 生成草案 + 插入位置选择 + **「确认新增」/「继续调整」**；
- 底部状态条显示 DOCX 导出就绪度（`not_docx` / `none` / `blocked` / `ready`）与「下载修改后的合同」按钮。

两套页面**都已实现且可达**，职责不同：

| 页面 | 路由 | 职责 |
|---|---|---|
| `AuditResult.vue` | `/audit/result` | **审核历史列表**：分页展示合同及其审核状态，可展开明细；入口来自导航「审核中心 → 审核历史」 |

## 七、权限流转操作

| 操作 | 页面位置 | 接口 | 前置条件 |
|---|---|---|---|
| 复核通过 | 合同详情顶部（reviewer/admin） | `POST /contracts/{id}/review?action=approve` | 合同 `status == "completed"`；**不得复核自己上传的** |
| 驳回重审 | 合同详情顶部（reviewer/admin） | `POST /contracts/{id}/review?action=reject` | 同上；驳回后当前有效审核记录置 `rejected`，合同回到 `parsed` |
| 验收通过 | 合同详情顶部（approver/admin） | `POST /contracts/{id}/approve` | 合同 `status == "reviewed"`；**不得验收自己上传的** |

## 八、模板管理（`TemplateList.vue`）

「赛题要求：支持加载企业标准条款模板（用户可配置）」的落地页面。

| 操作 | 接口 | 权限 |
|---|---|---|
| 列表（默认只返回各模板最新版本） | `GET /api/templates` | 任意登录用户 |
| 新建 | `POST /api/templates` | admin / reviewer |
| 详情 | `GET /api/templates/{id}` | 任意登录用户 |
| 修改（**生成新版本**，不覆盖旧记录） | `PUT /api/templates/{id}` | admin / reviewer |
| 版本链 | `GET /api/templates/{id}/history` | 任意登录用户 |
| 删除 | `DELETE /api/templates/{id}` | 仅 admin |

**版本机制**：`PUT` 不修改原行，而是插入一条 `version + 1` 的新记录，`previous_version_id` 指向旧版本；`GET /history` 沿该指针向前追溯并返回从最早到最新的完整链。

**模板如何影响审核**：条款比对时，若该合同类型在 `templates` 表里有最新版本，则**优先使用企业自定义模板**（`_db_template_clauses`），否则回退内置 `standard_clauses.json`。

> 前端「历史」按钮通过 `api/template.js` 的 `getTemplateHistory()` 拉取版本链并在对话框中展示（`TemplateList.vue` 已导入该函数）。

## 九、个人信息与个人 DeepSeek Key（`ProfileView.vue`）

- `GET /api/auth/profile` —— 返回用户名、邮箱、角色、`deepseek_key_configured`（布尔）；
- `PUT /api/auth/profile/deepseek-key` —— 保存**当前用户自己**的 Key，服务端用 Fernet 加密后写入 `users.deepseek_api_key_enc`；
- `DELETE /api/auth/profile/deepseek-key` —— 删除个人 Key，之后自动回退 `.env` 的系统默认 Key。

**生效优先级：个人 Key > `.env` 的 `DEEPSEEK_API_KEY`（系统默认 Key）。**

安全边界（代码保证）：

- 任何接口**只返回 `deepseek_key_configured: true/false`**，绝不返回 Key 本身或其片段；
- 管理员也看不到别人的 Key；
- Key 不写入日志、不下发到浏览器；
- 请求级绑定在 HTTP 中间件里完成，通过 ContextVar 隔离，多用户并发不会串 Key；
- 解密失败（如 `SECRET_KEY` 变更）按「未配置个人 Key」处理并告警，不让服务或请求崩溃。

## 十、用户管理（`UserManageView.vue`）

- `GET /api/auth/users` —— 用户列表（仅 admin，非 admin 返回 403）；返回 `deepseek_key_configured` 布尔值，不返回 Key；
- `PUT /api/auth/users/{user_id}/role` —— 修改角色（仅 admin）。

两条防锁死规则（服务端强制）：

1. **管理员不得修改自己的角色**（不能把自己锁在系统外）；
2. **系统必须至少保留一名 admin**（不能降级最后一个管理员）。

允许把他人提升为 admin（可以存在多个管理员）。

**第一个管理员如何产生**：公开注册只能得到 uploader，因此提供一次性部署开关 `BOOTSTRAP_ADMIN_USERNAME` —— 启动时若库中**0 个 admin** 且指定账号**已存在**，把该账号提升为 admin；**绝不自动建号、不改密码、不批量改其他用户**；系统已有 admin 时完全不动任何角色。

## 十一、首页仪表盘（`HomeView.vue`）

- Hero 区与核心能力介绍（能力卡片的图片来自 `public/images/feat-1..4.svg` + `hero.svg`）；

## 十二、审核报告导航与返回位置记忆（前端交互）

这是当前真实存在的前端功能，链路为：

```
合同详情 → 审核报告 Tab → 风险详情（#risk-<id>）→ 完整审核报告
   → 「返回审核报告」 → /contracts/:id?tab=audit → 恢复原来的审核报告滚动位置
```

实现要点（`constants/navigation.js` + `ContractDetail.vue`）：

| 机制 | 实现 |
|---|---|
| Tab 深链 | `/contracts/:id?tab=audit\|report\|text\|compare\|revise`；无法识别或空值 → **保持默认行为**（停在原始文本） |
| 风险深链 | `#risk-<风险记录id>`（`riskAnchorId`），由完整审核报告的 `scrollToHash()` 消费；只识别纯数字 id |
| 章节锚点 | `#clauses` → 完整报告「条款完整性检查」章节（`<section id="clauses">`）；条款缺失/偏离 Tag 一律降级定位到该章节（完整报告目前**没有条款卡片级 anchor**，因此不做下标猜测） |
| 风险上一项/下一项 | **只在完整审核报告页**提供（`← 上一项风险 / n / N / 下一项风险 →`），按显示顺序（高→中→低，组内按把握度）滚动，**不改变 URL** |
| 位置记忆采集 | `onBeforeRouteLeave`：仅当仍停在「审核报告」Tab 时，把 `window.scrollY` 写入 `sessionStorage['contract_<id>_report_return']` |
| 位置记忆恢复 | 进入 `?tab=audit` 时**一次性消费**该快照（读取即删除），用 `nextTick` + `requestAnimationFrame` 轮询直到能滚到目标高度（上限 1500ms），再 `scrollTo({behavior:'auto'})` |
| 为什么采集点在「离开合同详情」 | 两页滚动坐标不可比：完整报告页可高达数千像素，而审核报告 Tab 只有几百像素；用前者的 Y 恢复会被截断成「贴底」 |

**明确不做**：不写数据库、不新增接口、不跨浏览器会话保存；普通进入 `/contracts/:id` 或普通刷新**不会**跳到旧位置。

## 十四、统一响应格式与请求约定

- 业务响应统一为 `{ code: 0, message: "ok", data: ... }`；失败用 HTTP 状态码 + `detail`（中文，直接展示给用户）；
- 前端 `utils/request.js`：`baseURL = http://localhost:8080/api`（**绝对地址**）、默认超时 60s、请求拦截器注入 `Authorization: Bearer <token>`、响应拦截器**直接返回 `response.data`**（即已剥掉 HTTP 层）；
- 401 → 清除本地凭据并跳登录；403 → 「没有权限执行此操作」；其它 → 展示 `detail`；
- 网络错误（无响应）时**仅对 GET/HEAD/OPTIONS 静默重试一次**（1s 后），POST 不重试；
- 长耗时端点的专用超时（`api/timeouts.js`）：`revise` / `overview/confirm` 120s，`clause-comparison` / `add-clause-suggestion` 300s，`overview/plan` 180s，文件下载 120s，`locate-clause` 20s。

> 注意：由于 `request.js` 用的是**绝对 baseURL**，`vite.config.js` 里配置的 `/api` 开发代理实际上**不会被前端请求走到**；跨域由后端 `CORS_ORIGINS` 放行。

## 十五、当前功能的真实边界（如实列出）

1. **修订版统一输出 DOCX**：DOCX / 普通 PDF / 扫描 PDF / JPG / PNG / TIFF / BMP 均可经「审核 → 修改 → 导出修订版 DOCX」（非 DOCX 输入由 `parsed_text` 重建**中间 DOCX** 后再应用修订）；**不支持** PDF→PDF 或图片→图片导出，也不支持导出「未修改的原件」。
2. **审核报告可导出正式 PDF**：`GET /api/contracts/{id}/audit-report/pdf`（`services/report_pdf.py`，reportlab 纯 Python 排版，不依赖 Office）；**没有 Word / DOCX 报告导出**；报告页仍支持浏览器打印（`window.print()`）。
3. **审核报告页不显示审核人、报告编号、报告版本号、审批状态**——这些字段后端不存在。报告头部显示的「审核状态」是**合同状态**，不是审批状态。
4. **游客模式**：默认开启，未登录可浏览首页、登录页与合同列表页（列表数据仍需要登录才能取到）。
5. **前端角色判断仅用于 UI 显隐**，不构成权限边界；真正的边界在服务端。
