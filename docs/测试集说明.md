## 四、gold 标注口径

- **标注方式**：组员**背对背独立标注**——标注者只依据标注口径清单与合同正文判断，互不参考、互不影响，保证标注客观中立。
- **裁定流程**：标注分歧点经组员**人工复核**，结合法条与司法解释定标后写回 gold。
- **权威标准**：`docs/风险标注与Gold规范.md`，含三条上位规则（规则 A/B/C）与 R01–R13 逐类法理定义。

## 五、三大硬指标（实测）

| 硬指标 | 门槛 | 实测 |
|---|---|---|
| 法理分类准确率 | ≥85% | **98.6%**（145/147，147 份分类正式测试集；判错 2：技术 1 + 劳动 1） |
| 要素抽取 F1 | ≥80% | **93.7%**（披露样本加权综合 F1：双方 100.0 / 金额 87.2 / 期限 90.8 / 争议 96.3） |
| 风险识别精准率 | ≥75% | **76.6%**（TP 121 / FP 37 / FN 30，F1 78.3%） |
| 风险识别召回率 | ≥75% | **80.1%** |

> 分类历史冻结口径：97.62%（82/84，84 份原测试集，技术 1 份 + 劳动 1 份误判）——保留作版本对照，现正式口径已升级为 147 集 98.6%。

风险引擎经过多轮架构迭代，最终收敛为「**LLM 只抽事实 + Python 确定性规则裁决**」：LLM 不做风险判断，只抽取条款客观事实证据，由代码按 v1.2.4 口径的硬阈值裁决 R01–R12，保证可复现、同模板一致。

## 六、复现方式

| 指标 | 脚本 |
|---|---|
| 分类准确率 | `backend/evaluate/evaluate_rag.py`（RAG 少样本，走 147 集 `classification_test.json`） |
| 要素 F1 | `backend/evaluate/evaluate_elements.py` |
| 风险 P/R/F1 | `backend/evaluate/evaluate_evidence.py`（证据+裁决）/ `evaluate_risks.py`（双引擎六列） |

环境：DeepSeek `deepseek-chat`（分类 temperature=0.1，要素/证据 temperature=0.0）；要素结果有 md5 缓存、证据预计算于 evidence.json，可复跑。
