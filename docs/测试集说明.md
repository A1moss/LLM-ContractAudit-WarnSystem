## 四、gold 标注口径

- **盲标红线**：标注者只依口径清单 + 合同正文判断，**禁止参考规则引擎 / LLM 输出**（防回音室）。
- **流程**：豆包主标 → DS 背对背复核 → ChatGPT 按法理仲裁分歧 → 定标写回 gold。
- **权威标准**：`docs/风险标注口径.md`（v1.2.4），含三条上位规则（规则 A/B/C）与 R01–R13 逐类法理定义。

## 五、三大硬指标（实测）

| 硬指标 | 门槛 | 实测 |
|---|---|---|
| 法理分类准确率 | ≥85% | **98.81%**（83/84，仅 realtest_046 技术→承揽误判） |
| 要素抽取 F1 | ≥80% | **90.7%**（宏平均：双方 95.2 / 金额 84.6 / 期限 85.9 / 争议 96.3） |
| 风险识别精准率 | ≥75% | **76.6%**（TP 121 / FP 37 / FN 30，F1 78.3%） |
| 风险识别召回率 | ≥75% | **80.1%** |

风险引擎演进（v4→v6.4）：泛化 Prompt（P 24%）→ 严格 Prompt（R 73.5%）→ **证据 + 确定性裁决（P 76.6% / R 80.1%）**，核心是「LLM 只抽事实、Python 硬阈值裁决」。

## 七、诚实边界（答辩必读）

1. **分类口径**：正式指标 = 纯 LLM（98.81%）；历史上 kNN/RAG 的 93.49% 是同源泄漏（范本既建库又当考题），已作废，不得引用。
2. **补全风险条款是构造的**：47 份公告披露版合同的「补全风险条款」按行业惯例/官方范本构造并标注「补全」，用于让风险召回可测——报告必须写明，避免被误读为真实合同风险。
3. **R13 名实不符**：规则信号示警、单列报告、不进严格 F1（严格 F1 算 R01–R12 共 151 条）。
4. **要素披露率**：公告型样本期限/争议披露率 <100%，严格 F1 仅在披露样本上计算。
5. **引擎主口径**：`precise`（规则+LLM）为主；`fast`（纯规则引擎）作为确定性基线。
