## 二、技术点 → 本项目实现映射

| 技术点 | 本项目落地位置 |
|---|---|
| Transformer / LLM | `backend/ai/llm_client.py`（DeepSeek `deepseek-chat`，全项目唯一 LLM 出口） |
| RAG 检索增强 | `backend/ai/rag/`（ChromaDB 向量库 + BM25 → RRF 融合）；分类器 `backend/ai/classifier/rag_classifier.py`；建议层 `backend/ai/auditor/recommendation_engine.py`；新增条款 `search_similar_templates` |
| 句向量 / 语义检索 | `backend/ai/rag/vector_store.py`（`shibing624/text2vec-base-chinese` + `sentence-transformers`，`max_seq_length=512`） |
| 关键词 / 词面检索 | `backend/ai/rag/bm25.py` |
| 少样本提示（in-context learning） | `rag_classifier.py` 的范本示例块；`extractor.py` 的 few-shot 示例 |
| 信息抽取（要素 / 条款事实） | `backend/ai/extractor/extractor.py`（六要素）、`backend/ai/auditor/evidence_extractor.py`（R01–R12 风险事实证据） |
| 法律域理解 | 法条库 `backend/ai/knowledge/laws.json`（161 条）、标准条款库 `standard_clauses.json`（257 条）、风险法条映射 `RULE_LAWS` |
| 结构化过滤检索 | `backend/ai/matcher/matcher.py`（按合同类型结构过滤标准条款，而非用类型名做语义检索） |
| 图分析（跨条款风险） | `matcher._cross_clause_risks()`（标准条款库的 `depends_on` / `conflict_with` 字段 → 前置依赖缺失 / 条款互斥冲突） |
| P/R/F1 评测 | `backend/evaluate/evaluate_rag.py` / `evaluate_elements.py` / `evaluate_evidence.py` |
| 置信度校准 | `backend/ai/confidence.py`（按来源给基础置信度 + 多来源交叉验证上调） |
| 输出接地校验（grounding） | `recommendation_engine.recommendation_grounding_check()`（拦截无来源的数字 / 比例 / 法条） |
| 长文分块处理 | `backend/ai/chunker.py`（按条款标题边界分块，避免长合同尾部漏检） |

## 三、代码注释中出现的方法学名称（**未核验，不得作为文献引用**）

以下名称出现在代码注释或 docstring 中，用于说明设计思路的**思想来源**。本次整理**未对它们做独立的文献核验**，因此：

> **它们不构成参考文献，不得在申报材料中以「参考论文」形式引用。** 需要引用时，必须先完成检索核验后再补入第一节的文献清单。

| 出现的名称 | 出现位置 | 在代码中的用途说明 |
|---|---|---|
| `PAKTON` | `ai/matcher/matcher.py`、`ai/confidence.py` docstring | 结构化检索思想；多智能体法律问答的方法参考 |
| `GRAPH-GRPO-LEX`、`NCKG`、`LegalGraphRAG` | `ai/matcher/matcher.py` docstring | 合同图建模 / 嵌套合同知识图谱 / 图检索增强 —— 对应跨条款图分析 |
| `RCBSF` | `ai/reviser.py` docstring | Leader-Follower 层级 + 约束诱导的修订流程 |
| `Self-Consistency`、`KATE`、`kNN-LM`、`REALM` | `ai/classifier/classifier.py` 的采样投票、`rag_classifier.py` 的示例选择 | 多数投票与检索式示例选择的思想来源 |
| 多智能体验证 / ensemble calibration | `ai/confidence.py` docstring | 多来源一致时上调置信度的思想来源 |

> 另需说明：`ai/confidence.py` 的 docstring 中保留了「多 Agent 一致性置信度（`agent_confidence`）」的表述，属于**历史设计的残留注释**。当前生产代码中 `enrich_confidences()` 只有「规则来源」与「语义来源（LLM）」两类，**不存在多 Agent**；docstring 里的相关内容不应被理解为当前架构（详见 [`系统架构.md`](./系统架构.md) 第十二节）。
