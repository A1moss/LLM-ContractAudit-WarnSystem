# 风险规则说明

> 本文回答「**引擎怎么判**」，以当前生产代码为唯一真源：
> `backend/ai/auditor/rule_engine.py`（规则召回）与 `backend/ai/auditor/evidence_adjudicator.py`（确定性裁决）。
> 与之配套的是「**人怎么标 Gold**」，见 [`风险标注与Gold规范.md`](./风险标注与Gold规范.md)。

---

## 一、总览

系统共定义 **13 类风险**：**R01–R13**。

### 1.1 双引擎

| 检测路径 | 机制 | 出现场景 | 可复现性 |
|---|---|---|---|
| **规则引擎**（`rule_engine.py`） | 确定性正则 + 缺失型规则 + 信号组合 | ① `fast` 模式的全部内容；② `precise` 模式下**始终先跑**，但仅在证据抽取失败/异常时作为兜底结果 | 100% 确定 |
| **证据裁决**（`evidence_extractor` → `evidence_adjudicator`） | LLM 只抽事实证据 → Python 硬阈值裁决 **R01–R12** | `precise` 主口径（默认模式） | 裁决层零 LLM 自由发挥 |

### 1.2 三条必须准确理解的口径

1. **R01–R12 由证据裁决产出；R13 只由规则引擎产出。**
2. 在 `precise` 主口径下，若证据抽取成功，写入数据库的是 `adjudicate_risks()` 的结果 —— **此时 R13 不会出现**（裁决层不处理 R13）。R13 实际只会在 `fast` 模式、或 `precise` 模式证据抽取完全失败/异常降级时进入结果。
3. **规则数量 ≠ 风险数量 ≠ Gold 覆盖范围 ≠ F1 评测范围**。四者是不同的东西：

| 概念 | 值 | 说明 |
|---|---|---|
| 风险规则数量 | **13 类**（R01–R13） | 引擎定义了 13 条规则 |
| 进入严格 F1 的风险 | **R01–R12** | 评测口径（`evaluate_evidence.py` 只对 R01–R12 做集合比对） |
| **有 Gold 标注的风险** | **12 类中的 11 类**（**R05 完全没有 Gold**） | `realtest.json` 中 R05 的 Gold 数为 **0** |
| Gold 标签总数 | **152 条**（其中 R13 占 1 条） | 进入 R01–R12 严格 F1 的 Gold 为 **151 条** |

> ⚠️ **不得写成「13 类风险全部有 Gold」或「R05 有完整 F1」**。R05（保密期间不合理）在风险 Gold 中**没有任何标注样本**，因此**不存在 R05 的 P/R/F1**。
> 详情与来源结构见 [`数据集说明.md`](./数据集说明.md) 与 [`评测方法.md`](./评测方法.md)。

## 二、风险类型总表

**等级与法条的真源是代码**（`rule_engine.py::RISK_RULES` 的 `level`、`RULE_LAWS`）：

| 编号 | 引擎名称 | 默认等级 | 法条依据（`RULE_LAWS`） | 一句话含义 |
|---|---|---|---|---|
| R01 | 违约金过高 | **high** | 民法典第585条 | 违约金明显超过实际损失，法院可调减 |
| R02 | 无限责任 | **high** | 民法典第584条 | 赔偿责任无上限 / 覆盖一切损失、间接损失 |
| R03 | 单方解约权 | **medium** | 民法典第933/787条 | 一方可任意解除且无补偿 |
| R04 | 管辖条款不利 | **medium** | 民事诉讼法第35条 | 争议管辖法院 / 仲裁地明确偏向对方 |
| R05 | 保密期间不合理 | **high** | 民法典第501条 | 保密义务永久 / 无限期，无合理边界 |
| R06 | 知识产权归属不清 | **high** | 民法典第859/860/861条 | 成果 IP 归属失衡（无对价 + 明显不对称） |
| R07 | 付款条件不公平 | **high** | 民法典第525/526条 | 预付款过高 / 尾款苛刻且无里程碑 |
| R08 | 验收标准缺失 | **medium** | 民法典第621-623条、第845条 | 交付型合同缺乏客观验收机制 |
| R09 | 不可抗力条款缺失 | **medium** | 民法典第590条 | 交付型合同无不可抗力免责条款 |
| R10 | 竞业限制过宽 | **medium** | 劳动合同法第24条 | 竞业范围 / 地域 / 期限超出合理限度 |
| R11 | 自动续约陷阱 | **medium** | 民法典第734条 | 期满自动续约且无退出机制 |
| R12 | 数据隐私条款不当 | **high** | 个人信息保护法第23条 | 数据 / 个人信息共享无授权边界 |
| R13 | 疑似名实不符 | **high** | 民法典第146条 | 合同名义与实质法律关系不一致（**单列示警**） |

**等级与名称的内部一致性说明（如实列出）**：

- 等级在 `RISK_RULES`、`adjudicator.LEVELS`、前端 `riskTypes.js` 三处**完全一致**；
- 名称存在两处**不影响功能**的细微差异：`rule_engine` 把 R02 记为「无限责任**条款**」、R13 记为「疑似名实不符（真假合同）」，而 `evidence_adjudicator` / `recommendation_engine` / 前端统一为「无限责任」「疑似名实不符」；
- **数据库 `audit_records` 不存 `name` 字段**，前端展示名一律取 `frontend/src/constants/riskTypes.js::RISK_NAMES`（已与后端逐条对齐）。因此这处差异不会造成展示不一致。

## 三、规则引擎触发条件（`rule_engine.py::RISK_RULES`）

规则引擎对文本做确定性正则召回，命中后取上下文 ±30 字作为条款文本，并做等级细化。

| 编号 | 正则触发（简写） | 等级处理 |
|---|---|---|
| R01 | `违约.*?(\d{1,3})\s*[%％]` | `_refine_level`：比例 **>20% → high**；**≥10% → medium**；否则 **low** |
| R02 | `(全部损失\|一切责任\|无限责任\|所有损失\|任何.*?损失)` | high |
| R03 | `(甲方.*?有权.*?随时.*?(解除\|解约\|终止)\|任意.*?(解除\|解约\|终止).*?权)` | medium |
| R04 | `管辖.*?(被告\|对方\|乙方).*?法院` | medium |
| R05 | `保密.*?(永久\|无限期\|长期\|终身)` | high |
| R06 | `知识产权.*?归属.*?(对方\|乙方)` | high |
| R07 | `(预付.*?(\d{2,})\s*[%％]\|验收.*?(后\|完成).*?(不.*?付\|无.*?付))` | high |
| R08 | **规则型缺失检测**：全文不含「验收」且不含「验收标准」且不含「验收方式」 | medium |
| R09 | **规则型缺失检测**：全文不含「不可抗力」 | medium |
| R10 | `竞业.*?(所有行业\|全国\|永久\|终身\|(\d{2,})\s*年)` | medium |
| R11 | `期满.*?自动续` | medium |
| R12 | `(数据\|隐私\|个人信息).*?(共享\|提供\|转让\|披露)` | high |
| R13 | 见 §五 | high |

### 3.1 两层防误报机制

1. **安全模式过滤**（`SAFE_PATTERNS`）：命中后若上下文匹配安全模式则**不召回**。内置 6 条：

   | 安全模式 | 作用于 |
   |---|---|
   | `违约金.*?(不超过\|不高于\|≤).*?(\d{1,2})\s*[%％]` | R01 |
   | `违约金.*?(实际损失\|直接损失).*?(为限\|为上限)` | R01 |
   | `保密.*?(合同.*?终止.*?\d\s*年\|期满.*?\d\s*年)` | R05 |
   | `商业秘密.*?(合同.*?终止.*?\d\s*年\|期满.*?\d\s*年)` | R05 |
   | `知识产权.*?归属.*?(甲方\|我方\|双方共有)` | R06 |
   | `不可抗力.*?(包括\|含\|如下\|范围)` | R09 |

2. **否定语境过滤**（`_is_negated`）：R13 专用。命中位置前 8 字内出现「不得 / 禁止 / 不属于 / 非 / 不应 / 不得以 / 不得采用 / 排除」等否定词时，**不判 R13**（例如「不得采用劳务派遣」不触发名实不符）。

### 3.2 结果字段与去重

规则输出字段：`risk_type / level / name / clause_text / reason / suggestion / detection_method="rule" / confidence / related_law`。按 `(risk_type, 上下文前 40 字)` 去重。

置信度取 `ai/confidence.py::RULE_CONFIDENCE`（R01 0.90 / R02 0.92 / R03·R04·R10 0.85 / R05·R11·R12 0.88 / R06 0.86 / R07 0.90 / **R08·R09 0.72** / R13 0.85；未命中表时 0.80）。

> R08/R09 的置信度刻意最低：它们依赖「某词未出现」，**证据是缺席**，本质比显式命中更不确定。

## 四、证据裁决硬阈值（`evidence_adjudicator.py`）

`precise` 主口径：`evidence_extractor.py` 让 LLM 抽取结构化事实，`adjudicate_risks()` 按以下**硬阈值**裁决 **R01–R12**（R13 不在此层）。

| 编号 | 裁决条件（代码原文语义） |
|---|---|
| R01 | `exists == true` 且 `unit == "daily"` 且 `rate ≥ 0.005`（**日 5‰**） |
| R02 | `scope` 或 `absolute_text` 拼接文本含「预期 / 间接 / 无限 / 一切 / 全部损失」任一 |
| R03 | `termination` / `suspension` / `change` 三子项中**任一**满足 `arbitrary == true` 且 `no_compensation == true`（命中即 break，只产出一条） |
| R04 | `location_party == "乙方"` |
| R05 | `duration ∈ {永久, 无限, 不因终止而终止}` 且 `statutory_basis` 为假 |
| R06 | `has_consideration == false` 且 `imbalance_text` 非空 |
| R07 | `prepay_ratio ≥ 0.8`；**否则**若 `tail_ratio ≥ 0.3` 且 `has_milestone == false` |
| R08 | `is_delivery_type == true` 且**不满足**「`objective_basis` 为真 且 `basis_evidence` 非空」 |
| R09 | `is_delivery_type == true` 且**不满足**「`has_force_majeure` 为真 且 证据文本含「不可抗」 且 含机制词（通知 / 免责 / 不承担责任 / 解除 / 顺延 / 延期）」 |
| R10 | `has_noncompete == true` 且 `duration_years ≥ 5` 且 `scope ∈ {全国, 主营业务, 全行业}` |
| R11 | `mode` 归一化后等于 `silence_auto_renewal` |
| R12 | `has_personal_data == true` 且 `has_authorization_boundary == false` |

### 4.1 保证 LLM 字符串输出不漏判的三个归一化函数

- **`_num()`**：`"5%"` → 0.05、`"5‰"` → 0.005、剥离千分位逗号；无法解析返回 `None`（避免 LLM 输出字符串被 `isinstance` 判断静默跳过）。用于 R01 / R07 / R10。
- **`_normalize_scope()`**：R10 地域同义归一 —— 含「全国 / 全球 / 境内 / 不限地域 / 不限地区 / 所有区域」→ `全国`；含「主营」→ `主营业务`；含「全行业 / 所有行业」→ `全行业`。
- **`_normalize_mode()`**：R11 中英同义归一 —— `silence_auto_renewal` / 「沉默自动续约 / 沉默续约 / 自动续约 / 到期自动续 / 期满自动续」→ `silence_auto_renewal`；「主动续签 / 主动续约」→ `主动续签`。

### 4.2 结果字段

`risk_type / level / name / clause_text / reason / suggestion / detection_method="evidence" / confidence / related_law`，并按 `(risk_type, clause_text[:40])` 去重。

**关键实现细节**：`clause_text` **只取逐字原文**，不再用概念性描述或「违约金条款」这类兜底文字当定位文本 —— 因为 `clause_text` 会被用于在 `parsed_text` 中定位原文锚点，进而决定能否导出 DOCX 修订版。

## 五、R13 名实不符信号（`NAME_REALITY_SIGNALS`）

R13 只负责**检测 / 示警**，具体定性（假外包真派遣 / 名为买卖实为借贷 / 明股实债等）**交人工判定**。

触发条件：任一「名义信号 + 实质信号」对**同时命中**，且实质信号**不在否定语境**（命中即 break，只产出一条）。条款文本固定为 `合同同时出现名义类型与实质内容不一致的特征`。

| 名义信号 | 实质信号 |
|---|---|
| `服务外包 / 业务外包 / 人力外包 / 外包` | `劳务派遣 / 派遣单位 / 用工单位 / 被派遣` |
| `买卖 / 购销 / 采购 / 销售` | `回购 / 保底 / 固定回报 / 固定收益 / 年化 / 本息` |
| `投资 / 入股 / 增资 / 股权` | `固定收益 / 到期回购 / 保本 / 固定分红 / 年化` |
| `合作 / 联营 / 联合经营` | `固定租金 / 保底收益 / 固定费用` |

## 六、缺失型风险（R08 / R09）的判定要点

R08 / R09 是本系统中最需要谨慎对待的两类风险，因为它们的证据是**「某样东西不存在」**。

### 6.1 基准由「合同类型是否交付型」决定，不一刀切

- **必须有验收机制**：买卖 / 采购、承揽、建设工程、技术开发（交付成果类）→ 缺失标 R08；
- **未必有验收**：委托 / 中介（按成果或报酬结算）、租赁、物业 / 服务 → 缺失**不自动标** R08；
- **不可抗力**：只有交付型商业合同（买卖 / 承揽 / 建设 / 技术）缺失才标 R09；非交付型、劳动合同、保密协议不标 R09。

### 6.2 「有验收字样」≠「有验收机制」

仅有「验收合格后付款」这类**结果性表述**，而无标准 / 程序 / 责任主体的，仍标 R08。这正是裁决条件要求 `objective_basis` 与 `basis_evidence` **同时成立**才视为「有客观依据」的原因。

### 6.3 不可抗力必须是「有效条款」

仅出现「不可抗力」四个字不够。证据文本还必须含**机制性内容**（通知 / 免责 / 不承担责任 / 解除 / 顺延 / 延期）。这排除了「可能存在不可抗力风险」这类**风险提示句**被误当成条款。

## 七、Gold 覆盖情况（与规则数量的区别）

`backend/evaluate/realtest.json`（84 份合同）中各类风险的 Gold 标签实际数量：

| 编号 | Gold 条数 | 是否进入严格 F1 |
|---|---|---|
| R01 违约金过高 | 21 | ✅ |
| R02 无限责任 | 15 | ✅ |
| R03 单方解约权 | 12 | ✅ |
| R04 管辖条款不利 | 8 | ✅ |
| **R05 保密期间不合理** | **0** | ⚠️ **无 Gold**，不参与 F1 |
| R06 知识产权归属不清 | 7 | ✅ |
| R07 付款条件不公平 | 6 | ✅ |
| R08 验收标准缺失 | 25 | ✅（但见下方结构性限制） |
| R09 不可抗力条款缺失 | 28 | ✅（但见下方结构性限制） |
| R10 竞业限制过宽 | 7 | ✅ |
| R11 自动续约陷阱 | 16 | ✅ |
| R12 数据隐私条款不当 | 6 | ✅ |
| R13 疑似名实不符 | 1 | ❌ 单列示警，不进严格 F1 |
| **合计** | **152** | 进入 R01–R12 严格 F1 的为 **151** |

**由此可得出三条必须如实陈述的结论：**

1. **R05 没有 Gold，因此不存在完整的 R05 F1。** 正式 F1（78.3%）覆盖的是 R01–R12 中**实际有 Gold 的风险**；R05 在指标里既没有 TP 也不贡献样本。
2. **R13 不纳入当前 F1**。它只由规则引擎产出、且明确「定性交人工」，因此被单列示警。
3. **R08 / R09 的 Gold 覆盖存在结构性限制**。它们是缺失型风险，而 Gold 中相当一部分「缺失」标注来自**公开披露合同的补全/构造**（详见 [`数据集说明.md`](./数据集说明.md)），并非全部来自自然缺失的真实合同；因此这两类的样本分布与真实业务分布存在偏差，其 P/R 的解释力弱于显式命中型风险（如 R01/R02/R11）。
