# 风险规则说明（R01–R13）

> 本文档描述当前 `dev` 分支**生产代码**中的风险判定规则，以 `backend/ai/auditor/rule_engine.py` 与 `backend/ai/auditor/evidence_adjudicator.py` 为准。
> 与之配套的人工 gold 标注规范见 [`风险标注与Gold规范.md`](./风险标注与Gold规范.md)。两者关系：本文件回答「引擎怎么判」，标注规范回答「人怎么标 gold」。

---

## 一、总览

系统共定义 **13 类风险**（R01–R13），其中：

- **R01–R12**：进入严格 P/R/F1 评测；
- **R13（疑似名实不符）**：规则信号**单列示警**，不进严格 F1（具体定性交人工）。R13 仅由规则引擎检测（`fast` 模式，或 `precise` 证据抽取失败降级时输出）；`precise` 主口径的证据裁决只处理 R01–R12。

风险判定采用「**双引擎**」：

| 检测路径 | 机制 | 适用模式 | 可复现性 |
|---|---|---|---|
| 规则引擎 | 确定性正则 + 缺失型规则 | `fast` 基线，始终先跑；`precise` 异常兜底 | 100% 可复现 |
| 证据裁决（v6.4） | LLM 只抽事实证据 → Python 硬阈值裁决 | `precise` 主口径 | 裁决层确定性、零 LLM 自由发挥 |

设计原则（数据验证过）：**LLM 不直接判断风险**，只抽取条款客观事实（数值、范围、管辖地、验收机制等），风险判定全部由 Python 代码按固定阈值完成，保证同模板一致、可复现。

## 二、风险类型总表

| 编号 | 名称 | 默认等级 | 法条依据 | 一句话含义 |
|---|---|---|---|---|
| R01 | 违约金过高 | high | 民法典 585 | 违约金明显超过实际损失，法院可调减 |
| R02 | 无限责任 | high | 民法典 584 | 赔偿责任无上限 / 覆盖一切损失、间接损失 |
| R03 | 单方解约权 | medium | 民法典 933 / 787 | 一方可任意解除且无补偿 |
| R04 | 管辖条款不利 | medium | 民事诉讼法 35 | 争议管辖法院/仲裁地明确偏向对方 |
| R05 | 保密期间不合理 | high | 民法典 501 | 保密义务永久/无限期，无合理边界 |
| R06 | 知识产权归属不清 | high | 民法典 859/860/861 | 成果 IP 归属失衡（无对价 + 明显不对称） |
| R07 | 付款条件不公平 | high | 民法典 525/526 | 预付款过高 / 尾款苛刻且无里程碑 |
| R08 | 验收标准缺失 | medium | 民法典 621-623、845 | 交付型合同缺乏客观验收机制 |
| R09 | 不可抗力条款缺失 | medium | 民法典 590 | 交付型合同无不可抗力免责条款 |
| R10 | 竞业限制过宽 | medium | 劳动合同法 24 | 竞业范围/地域/期限超出合理限度 |
| R11 | 自动续约陷阱 | medium | 民法典 734 | 期满自动续约且无退出机制 |
| R12 | 数据隐私条款不当 | high | 个人信息保护法 23 | 数据/个人信息共享无授权边界 |
| R13 | 疑似名实不符 | high | 民法典 146 | 合同名义与实质法律关系不一致（单列示警） |

> 法条映射的唯一真源：`backend/ai/auditor/rule_engine.py::RULE_LAWS`。

## 三、规则引擎触发条件（`rule_engine.py::RISK_RULES`）

`fast` 模式与 `precise` 模式的兜底路径使用确定性正则召回：

| 编号 | 正则触发（简写） | 等级细化 |
|---|---|---|
| R01 | `违约…{1-3位数}% / ％` | `_refine_level`：比例 >20% → high；≥10% → medium；否则 low |
| R02 | `全部损失 / 一切责任 / 无限责任 / 所有损失 / 任何…损失` | high |
| R03 | `甲方…有权…随时(解除/解约/终止)` 或 `任意(解除/解约/终止)…权` | medium |
| R04 | `管辖…(被告/对方/乙方)…法院` | medium |
| R05 | `保密…(永久/无限期/长期/终身)` | high |
| R06 | `知识产权…归属…(对方/乙方)` | high |
| R07 | `预付…{≥2位数}%` 或 `验收(后/完成)…(不…付/无…付)` | high |
| R08 | 全文无「验收 / 验收标准 / 验收方式」 | medium |
| R09 | 全文无「不可抗力」 | medium |
| R10 | `竞业…(所有行业/全国/永久/终身/≥2位数年)` | medium |
| R11 | `期满…自动续` | medium |
| R12 | `(数据/隐私/个人信息)…(共享/提供/转让/披露)` | high |
| R13 | 见 §五「名实不符信号」 | high |

规则引擎还内置两层防误报：

1. **否定语境**（`_is_negated`）：命中位置前 8 字内出现「不得 / 禁止 / 不属于 / 非 / 不应 / 排除」等否定词 → 不判；
2. **安全模式**（`SAFE_PATTERNS`）：如「违约金不超过 20%」「知识产权归甲方/双方共有」「不可抗力包括…」「赔偿以实际损失为限」等 → 判为安全，不召回。

## 四、证据裁决硬阈值（`evidence_adjudicator.py`，v6.4 冻结）

`precise` 主口径：`evidence_extractor.py` 让 LLM 抽取结构化证据，`adjudicate_risks()` 按以下**硬阈值**裁决 R01–R12：

| 编号 | 裁决条件（代码原文语义） |
|---|---|
| R01 | 证据 `exists=true` 且 `unit=="daily"` 且 `rate ≥ 5‰`（0.005） |
| R02 | `scope` 或 `absolute_text` 含「预期 / 间接 / 无限 / 一切 / 全部损失」任一 |
| R03 | `termination / suspension / change` 任一满足 `arbitrary=true` 且 `no_compensation=true` |
| R04 | `location_party == "乙方"` |
| R05 | `duration ∈ {永久, 无限, 不因终止而终止}` 且 `statutory_basis` 为空 |
| R06 | `has_consideration=false` 且 `imbalance_text` 非空 |
| R07 | `prepay_ratio ≥ 0.8`；或 `tail_ratio ≥ 0.3` 且 `has_milestone=false` |
| R08 | 交付型合同（`is_delivery_type=true`）且无客观验收依据（`objective_basis` 为空或 `basis_evidence` 为空） |
| R09 | 交付型合同且无含机制词（通知/免责/不承担责任/解除/顺延/延期）的有效不可抗力条款 |
| R10 | `has_noncompete=true` 且 `duration_years ≥ 5` 且 `scope ∈ {全国, 主营业务, 全行业}` |
| R11 | `mode` 归一化为「沉默自动续约」（`silence_auto_renewal`） |
| R12 | `has_personal_data=true` 且 `has_authorization_boundary=false` |

辅助归一化函数（保证 LLM 字符串输出不漏判）：
- `_num()`：把 `"5%"`→0.05、`"5‰"`→0.005、整数/浮点/字符串统一转 float；
- `_normalize_scope()`：R10 地域同义归一（全国/全球/境内/不限地域 → 「全国」；主营 → 「主营业务」）；
- `_normalize_mode()`：R11 中英同义归一（「沉默/自动/到期自动/期满自动续约」→ `silence_auto_renewal`）。

裁决结果字段：`risk_type / level / name / clause_text / reason / suggestion / confidence / related_law / detection_method`，并做「同类型 + 同条款前 40 字」去重。

## 五、R13 名实不符信号（`NAME_REALITY_SIGNALS`）

R13 只负责「检测/示警」，具体定性（假外包真派遣 / 名为买卖实为借贷 / 明股实债等）交人工。触发条件：**任一「名义信号 + 实质信号」对同时命中**，且实质信号不在否定语境：

| 名义信号 | 实质信号 |
|---|---|
| 服务外包 / 业务外包 / 人力外包 / 外包 | 劳务派遣 / 派遣单位 / 用工单位 / 被派遣 |
| 买卖 / 购销 / 采购 / 销售 | 回购 / 保底 / 固定回报 / 固定收益 / 年化 / 本息 |
| 投资 / 入股 / 增资 / 股权 | 固定收益 / 到期回购 / 保本 / 固定分红 / 年化 |
| 合作 / 联营 / 联合经营 | 固定租金 / 保底收益 / 固定费用 |

## 六、缺失型风险（R08/R09）判定要点

- 由「合同类型是否交付型」决定基准，不一刀切：
  - **必有验收机制**：买卖/采购、承揽、建设工程、技术开发（交付成果类）→ 缺失标 R08；
  - **未必有验收**：委托/中介（按成果/报酬结算）、租赁、物业/服务 → 缺失不自动标 R08；
  - **不可抗力**：仅交付型商业合同（买卖/承揽/建设/技术）缺失标 R09；非交付型、劳动合同、保密协议不标 R09。
- 有「验收」字样 ≠ 有验收机制；仅有「验收合格后付款」这类结果性表述而无标准/程序/责任主体的，仍标 R08。
